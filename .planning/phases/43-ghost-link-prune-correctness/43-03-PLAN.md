<objective>
Implement the two GHOST-08 attemptCount semantic fixes and the GHOST-07 source-less coverage, and persist the evidence string on every write. Change the `persistLiveness` reset rule from "reset on any live-or-unknown" to: `live` resets to 0, `unknown` PRESERVES the prior count (no increment, no reset), `no-url` is 0 — while KEEPING the sidecar DECR on dead→unknown (the event exits dead-membership even though its consecutive-dead history is preserved; these are independent axes). Replace `buildProbeCandidates`'s silent drop of source-less events with an explicit `no-url` write (no fetch) and a `classifiedNoUrl` count threaded into the cron log line.

Purpose: The flaky-host bug — a host alternating dead→unknown→dead reset to 0 on every `unknown`, so it never reached the `>=3` cron gate — is fixed by `unknown` preserving the count (D-10). Transient failures still never count toward prune (`unknown` never increments), but a genuine repeat offender eventually accumulates and becomes cron-prunable, while a blip that recovers to `live` still fully resets. Source-less events are no longer invisible to the pipeline: prune can SEE them as `no-url` and explicitly skip them (D-08 — pruning events merely for lacking a URL would make prune MORE aggressive, which the phase goal forbids).

Output: split attemptCount derivation + evidence-on-writer in `persistLiveness`; `no-url` side-effect + `classifiedNoUrl` in `buildProbeCandidates`; updated cron log line; flipped/extended sweep test.
</objective>
