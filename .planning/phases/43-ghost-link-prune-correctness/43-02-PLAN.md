<objective>
Implement the GHOST-06 soft-404 body heuristic: a capped GET on every 200 response feeds the decoded 16 KiB head into a pure exported `classifySoft404(bodyText, finalUrl, originalUrl)` helper that evaluates three signals in D-02 order — (a) not-found markers in `<title>`/body, (b) redirect-to-home, (c) near-empty content — with a precision-first tie-break (D-03: any ambiguity → `live`). No headless browser, no JS evaluation.

Purpose: Status codes miss soft-404s (publisher serves a "page not found" or empty shell with HTTP 200). The asymmetric error budget is binding: a missed dead link is acceptable, a flagged-live link is NOT — so the heuristic is conservative and the tie-break is `live`. Extracting `classifySoft404` as a pure function gives it a table-driven test with no fetch mocking.

Output: `classifySoft404` + `readCappedBody` helpers, three hard-coded module constants (D-20), `probeUrl` 200-branch wiring, and an extended probe test.
</objective>
