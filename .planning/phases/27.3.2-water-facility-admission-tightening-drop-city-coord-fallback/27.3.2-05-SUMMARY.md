## Decisions Made

1. **Preserved branch 6 (bare `FACILITY_TYPE_LABELS[facilityType]`) as defense-in-depth** rather than replacing it with an unreachable-case throw. Rationale: if a future plan adds a new `facilityType` exempt from the admission Latin-gate (mirroring the current desal exemption), that exempt type would silently produce a bare-type label — preferable to a runtime throw in a hot extractor path. JSDoc explicitly labels branch 6 "defense-in-depth only."

2. **Typed `nearestCity` as `ReturnType<typeof findNearestCity>`** rather than inlining `{ name: string; distanceKm: number; population: number } | null`. Plan's `<interfaces>` block explicitly prescribes this and `findNearestCity`'s return type is the canonical source. Downstream field additions propagate automatically.

3. **Kept `extractLabel` module-private** — the plan's Task 1 `<action>` explicitly instructs not to export ("Plan 06 can decide"). Current call graph is just `extractLabel ← normalizeWaterElement`, so private visibility carries zero cost. If Plan 06 chooses to unit-test extractLabel directly it can export in a dedicated commit.

4. **Rewrote the JSDoc rather than appending** — the pre-existing JSDoc was 1 line ("Extract an English label from OSM tags"). The full 6-step resolution order + byte-identity invariant + defense-in-depth rationale is new information that warrants a dedicated block. Matches the density of surrounding JSDoc in the admission decision functions.
