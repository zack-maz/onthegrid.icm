## Decisions Made

1. **Cases 4 + 5 asserted the exact synthesized label string via `normalizeWaterElement`** rather than `verdict: 'admit'` only. The plan explicitly gave discretion: "leave cases 4/5 asserting verdict: 'admit' only — the label synthesis is independently covered by client-side Plan 08 tests and by the Plan 10 snapshot regeneration grep." I chose the stronger assertion because:
   - `normalizeWaterElement` takes only 2 args (`el`, `stressLookup`) with both fixtures already in this file, so the cost was +~15 lines per case with zero new mocks.
   - It closes the label-synthesis branch coverage server-side at the earliest possible plan — Plan 08 client tests and Plan 10 snapshot grep are downstream consumers, and catching a synthesis regression here is 1-2 days earlier in the wave sequence.
   - Matches PATTERNS.md Pattern 3's explicit endorsement of the route-through-normalizeWaterElement pattern when `extractLabel` is module-private.

2. **Shared `mockStress` + `stressLookup` at the top of the describe block** rather than per-test. Reduced repetition; matches the idiom used in the 27.3.1 Plan 10 describe block further down the file. No test uses a non-default stress value, so a shared stub is correct.

3. **Case 3's tags include `wikidata: 'Q2'`** to match the plan's `<interfaces>` block exactly. This is deliberately redundant for the admission verdict (step 3b fires before `isNotable` / compound gate would be reached), but it serves as a defense-in-depth "even wikidata doesn't rescue non-Latin-only tags" assertion — a pre-Plan-04 wikidata shortcut would have falsely admitted this fixture.

4. **Route-through uses real `findNearestCity`, not a stub.** Case 4's `(22.5, 37.5)` was chosen because it's offshore Red Sea with no `CITY_DATA` entry within 150km (Jeddah at 21.4858, 39.1925 is ~200km away, Medina at 24.4672, 39.6024 is ~291km). Case 5's `(21.5, 39.1)` is ~5km from Jeddah (21.4858, 39.1925). Both cases exercise the real `findNearestCity` implementation end-to-end, catching any future regression in the 150km threshold.

5. **Kept the plan's exact describe-block title** including the em-dash (`"Phase 27.3.2 admission tightening — no_resolved_name + desal synthesis"`). Matches PATTERNS.md section heading verbatim; consistency across planning artifacts keeps grep queries reliable.

6. **Did NOT export `extractLabel`** from `server/adapters/overpass-water.ts` for direct unit testing. Plan 05 left the decision to Plan 06, and route-through-normalizeWaterElement achieves the same coverage without changing the adapter's export surface. Keeping `extractLabel` module-private preserves the invariant that its 5-arg signature is an internal contract, not a public one.
