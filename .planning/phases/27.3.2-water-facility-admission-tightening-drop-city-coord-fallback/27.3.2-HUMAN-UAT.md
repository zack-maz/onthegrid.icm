### 1. Bare-label facility disposition

expected: User decides how to handle the 4 bare-label entries in the regenerated snapshot:

- `water-28749940` (desalination, label `"Desalination Plant"`)
- `water-467571237` (**dam**, label `"Dam"`) — **not discussed at Plan 10 Task 3 checkpoint**
- `water-621965314` (desalination, label `"Desalination Plant"`)
- `water-718088667` (desalination, label `"Desalination Plant"`)

Root cause: OSM `name` tag is literally the bare type string. `hasLatinLabel` passes (it's valid Latin script), so the Plan 04 admission gate admits it and Plan 05's extractLabel synthesis branches never fire.

The non-desal dam (`water-467571237`) is the more concerning case — the whole point of Plan 04 was to reject non-desal facilities without real names. User's Plan 10 Task 3 "accept and ship" decision was framed as covering 3 bare desal entries; it did not explicitly consider the 1 non-desal case.

Proposed fix (~5 lines in `server/adapters/overpass-water.ts`):

```typescript
const GENERIC_OSM_NAME_RE = /^(dam|reservoir|desalination(\s+plant)?)$/i;
// inside extractLabel, after the Latin-check branches:
if (primary && GENERIC_OSM_NAME_RE.test(primary.trim())) {
  // treat as missing — fall through to desal synthesis or no-name rejection
}
```

For desal: bare labels would cascade into the "Desalination Plant near {city}" synthesis branches.
For non-desal: bare labels would push the admission decision into `no_resolved_name` rejection (element dropped entirely from snapshot).
