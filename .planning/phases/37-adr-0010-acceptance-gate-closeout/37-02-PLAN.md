GREEN definition (D-07 strict reading):

- workflow run exits 0 (GitHub Actions shows green checkmark) AND
- the sidecar payload returned by `/api/audit-status` has `allTiersGreen === true`

Both must be true. If workflow exited 0 but `allTiersGreen === false` (impossible per Phase 28.2.5 D-09 — the step exits non-zero when allTiersGreen=false — but defensive check), or workflow exited 1, or any `tierStatus.*` value is not `"healthy"`: this run is RED.

RED-mid-sequence rule (D-07 hard reset):

- If runs 1 or 2 land green but run 3 lands red → streak wipes. Operator restarts from run 1 (NOT just re-runs the failed run).
- Same for any other position. The 3-in-a-row constraint is strict.
- Document any red runs that occurred during the streak in the framing-gap callouts row (Plan 37-03 finalizes the framing-gap section, but Plan 37-02 may pre-populate the deviation row in the draft).

CADENCE preference (D-06):

- Preferred: 1 run per day across 24-48 hours (≥24h between consecutive runs, ≤48h total span from run 1 to run 3).
- Why: crosses the 04:00 UTC daily cron tick at least once; closest to the spirit of the Phase 31 7-day watch; most robust evidence of stability across cron tick.
- Acceptable per D-08 NOTE: operator may compress to back-to-back (~10-30 min apart) if rationale is logged. Plan 37-02 surfaces this deviation in the draft framing-gap callouts row.
