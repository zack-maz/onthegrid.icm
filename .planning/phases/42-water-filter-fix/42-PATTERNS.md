### `server/adapters/overpass-water.ts` — spatial dedup fix (adapter, transform)

**Analog:** itself, lines 1198-1212 (the loop being replaced). Extraction-to-pure-function precedent: `computeAdmissionDecision` (Phase 27.3.1 R-06 D-20).

**Current buggy pattern** (lines 1198-1212) — name-blind, order-dependent, inline:

```typescript
// Deduplicate by OSM ID
const unique = new Map<string, WaterFacility>();
for (const f of all) unique.set(f.id, f);

// D-05: Spatial dedup (50m, same facilityType)
const deduped: WaterFacility[] = [];
for (const f of Array.from(unique.values())) {
  const isDupe = deduped.some(
    (existing) =>
      existing.facilityType === f.facilityType &&
      haversine(existing.lat, existing.lng, f.lat, f.lng) < 0.05,
  );
  if (!isDupe) deduped.push(f);
  else stats.rejections.duplicate++;
}
```

**Defects (from RESEARCH):** (1) no name comparison in the `isDupe` predicate → distinct named facilities collapse (violates WATER-FILTER-02); (2) `Array.from(unique.values())` iterates in Overpass return order and keeps first-seen → non-deterministic survivor (the "intermittent" symptom).

**Fix pattern to copy from** (RESEARCH Pattern 1, derived from this same loop + D-04/D-05/D-07): extract to an exported pure function so it is unit-testable without mocking Overpass (Pitfall 3 / Open Question 3), keeping `haversine` (line 271) and the `< 0.05` = 50m constant unchanged (D-05):

```typescript
export function spatialDedup(facilities: WaterFacility[]): {
  kept: WaterFacility[];
  collapsed: number;
} {
  // D-07: deterministic survival order — highest notabilityScore, tie-break lowest osmId.
  const ordered = [...facilities].sort(
    (a, b) => (b.notabilityScore ?? 0) - (a.notabilityScore ?? 0) || a.osmId - b.osmId,
  );
  const kept: WaterFacility[] = [];
  let collapsed = 0;
  for (const f of ordered) {
    const fname = normName(f);
    const isDupe = kept.some((existing) => {
      if (existing.facilityType !== f.facilityType) return false; // D-05: same type retained
      if (haversine(existing.lat, existing.lng, f.lat, f.lng) >= 0.05) return false; // D-05: 50m retained
      const ename = normName(existing);
      return ename === fname || ename === '' || fname === ''; // D-04: collapse only on name-match or one-side-unnamed
    });
    if (!isDupe) kept.push(f);
    else collapsed++;
  }
  return { kept, collapsed };
}
```

**Name-normalization helper** — field choice is `f.label` (always populated by `extractLabel` at line 984, reflects romanization; Pitfall 4 warns against `nameLatin` which is only set when `applyRomanizedName` fires). D-04 marks this Claude's discretion, "keep it simple":

```typescript
function normName(f: WaterFacility): string {
  return (f.label ?? '').toLowerCase().replace(/\s+/g, ' ').trim();
}
```

**Call-site replacement** (lines 1202-1212 become):

```typescript
const { kept: deduped, collapsed } = spatialDedup(Array.from(unique.values()));
stats.rejections.duplicate += collapsed;
```

**Constraint reminders (anti-patterns, from CONTEXT + RESEARCH):**

- Do NOT touch `computeAdmissionDecision` / `hasLatinLabel` (D-06; G1 stays green by construction — the fix is downstream of admission).
- Do NOT widen/shrink the 50m window (D-05).
- `stats.rejections.duplicate` is the SUMMED bucket (line 1211); `byTypeRejections[*].duplicate` is structurally always 0 post-merge (Pitfall 1) — the diagnosis cites the summed field + the two-run ID-set diff, not a per-type duplicate count.
