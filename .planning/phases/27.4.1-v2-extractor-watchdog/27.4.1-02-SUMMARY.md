## Decisions Made

- **Literal-fallback chain over non-null assertion (D-18):** Chose `BACKOFF_MS[attempt] ?? BACKOFF_MS[0] ?? 1000` over `BACKOFF_MS[attempt]!`. The non-null assertion would claim a runtime guarantee the tuple definition doesn't enforce; the literal fallback is defense-in-depth — if the tuple shape ever changes to `[]`, the code still returns a sane 1000ms delay rather than crashing. Aligned with D-17 "non-null assertions are LAST resort."
- **Source code canonical (D-19):** Test expectation brought into alignment with shipped code, NOT vice versa. The color `[220, 100, 90]` has been live on the map since Phase 27 commit 709fa15; flipping the code value now would be a visible regression for zero documented reason. Code is canonical per D-19.
- **`<button>` → `<span>` semantic tag swap (D-20 extension):** Plan prescribed the tag swap. This is correct beyond the plan's explicit rationale: a button with no onClick that dispatches nothing is an a11y defect — screen readers still announce it as "button" and focus traversal still lands on it. `<span>` is the semantically-correct tag for a purely-display badge.
- **Preserved fetchVersion useEffect (D-20):** The plan explicitly required keeping the GET `/api/events/llm-pipeline` fetch on mount. This is the difference between a LIVE indicator (knows the current effective version) and a hardcoded label (shows "v2" forever even if operator POSTs to v1). The mount fetch is what makes the pill useful at all.
