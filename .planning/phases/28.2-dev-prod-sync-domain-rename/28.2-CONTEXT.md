### Dev → Prod Feature Promotion

The `shouldRenderDashboard()` helper in `src/lib/dashboardAuth.ts` and `server/middleware/dashboardAuth.ts` is the canonical Bearer gate. "Bearer-gated graduate" below means: `import.meta.env.DEV` short-circuit OR a stored `DASHBOARD_PASSWORD` Bearer token in localStorage / `Authorization` header.

- **D-05:** **Per-field opt-in** for currently-dev-only debug fields. No blanket "graduate everything" rule. Each field decided individually.
- **D-06:** **Graduate to Bearer-gated prod**:
  - Event ID + OSM ID values (currently dev-only in `EventDetail.tsx`, `WaterFacilityDetail.tsx`).
  - LLM confidence + provenance fields (currently dev-only in `EventDetail.tsx`).
  - `EntityTooltip` dev info block (raw entity data dump in `src/components/map/EntityTooltip.tsx:124`).
- **D-07:** **Stay dev-only forever** (do NOT graduate):
  - `WaterFacilityDetail` `notabilityScore` debug field.
  - `NotificationCard` severity score numeric — explicitly preserved per `memory/project_dev_score_display.md`.
  - `MapDevExposer` programmatic `window.__map` handle in `src/components/map/BaseMap.tsx:458` — testing primitive, footgun risk in prod.
- **D-08:** **Bearer-gated graduate** for operator-control endpoints:
  - `POST /api/events/llm-pipeline` (runtime v1/v2/v3 swap) — operator can swap pipeline version from the deployed dashboard during incidents without a CLI session.
  - `POST /api/events/llm-replay/:groupKey` — operator can re-extract a single group with the current prompt without a `vercel dev` round-trip. **Pitfall 6 dual-gate is preserved**: the endpoint never writes to `events:llm:v3` cache, only returns the diff.
- **D-09:** **No new debug-field surfaces** are added in Phase 28.2 — the audit is "promote what exists" only.

### Dashboard Tab Consolidation + API Connectivity Audit (added 2026-05-04)

The DevApiStatus modal currently renders two overlapping observability surfaces — `Overview` (client-perspective polling stores + LLM Pipeline progress) and `All APIs` (server-perspective `/api/health` aggregate of 16 endpoints, tier-grouped). The existing CLAUDE.md "API reliability (W2)" entry already establishes the `HealthStatusProvider` single-poll guarantee (HealthBanner + DevApiStatus share one `/api/health` cycle) — Phase 28.2 must preserve that contract verbatim. These nine decisions resolve the "have All APIs replace Overview, add more detail, ensure all APIs are connecting" directive (2026-05-04).

- **D-22: Merge Overview into All APIs.** Delete the `Overview` tab entirely. Polling-store metrics (count, avg response time, success rate, next-poll countdown, recent fetches) and the existing `LLMPipelineSection` block fold into the unified panel. Contract: **nothing currently visible in Overview goes missing**. Polling-store data lands in the per-endpoint expanded row alongside the existing JSON dump; `LLMPipelineSection` renders beneath the table as its own block. `DevApiStatusOverviewTab` (`src/components/ui/DevApiStatus.tsx:361`) is deleted; `DevApiStatusAllApisTab` (`src/components/ui/DevApiStatus.tsx:995`) absorbs the responsibilities. Tab-state default in `uiStore` shifts from `'overview'` to `'allApis'` (or whatever D-27 names it).
- **D-23: Four new diagnostic blocks** beyond the D-22 fold-in baseline:
  1. **Tier-grouped summary banner** at top of tab — single-line `"15 of 16 healthy · 1 degraded · 0 unhealthy"` with per-tier breakdown (critical / non-critical / cron). Cheap; reads from `health.summary` already computed in `server/routes/health.ts:261`.
  2. **Per-endpoint quality metrics** in the expanded row, surfacing what's already computed: events → precision histogram (exact/city/region) + LLM-vs-raw ratio (`eventQuality` memo in `DevApiStatus.tsx:545`); water → admission percentage from `filterStats`; flights → unidentified count.
  3. **Per-endpoint manual retry button** in the expanded row (Bearer-gated). Triggers an immediate poll for that store via existing store actions (e.g., `useFlightStore.getState().fetchNow()` pattern) or a cache-bust route call where applicable. Net new behavior; small surface.
  4. **Recent-fetch sparkline** per endpoint row — inline 10-dot strip (ok=green, fail=red) sourced from existing `recentFetches[]` selector data already in each store. Visual stability glance.
- **D-24: Connectivity guarantee = three-pronged deliverable.** (a) **Manual audit + fix** — walk every adapter (16 endpoints from `PROBE_STRATEGIES` in `server/routes/health.ts:227` plus underlying upstream sources), verify a fresh fetch lands non-empty data, fix any that are broken/stale. (b) **Vitest smoke suite** — new `src/__tests__/api-connectivity.test.ts` (or split client + server suites if cleaner) hits every adapter and asserts ≥1 successful fetch with non-empty body. (c) **Critical-banner verification** — confirm `HealthBanner` actually fires and remains visible during a critical-tier outage (existing `HealthBanner.test.tsx` covers the unit; this adds an integration trace). **Explicitly rejected:** dev-mode startup probe — prod is what matters per user directive.
- **D-25: Audit runs as the final wave (W6) against the deployed prod URL only.** Per user directive: "make sure its working on PROD, thats where it matters." The audit is the **last** wave of 28.2. It runs **after** D-03 domain rename, D-06/D-08 dev/prod gates, D-04 Bearer-bypass, and D-22/D-23 merge have all merged to main. Target URL is `https://otg-iran-monitor.vercel.app`. Local-dev audit pass during W5 plan execution is acceptable as an early gut-check, but the gating evidence for W6 is the prod-URL run.
- **D-26: Bearer-gate the unified tab** via `shouldRenderDashboard()`, consistent with D-06/D-08. Today `All APIs` is always-visible (Phase 28.1 W2 contract `showAllApisTab = true`); the merged tab inherits the canonical Bearer pattern instead. Dev short-circuit + `DASHBOARD_PASSWORD` Bearer in localStorage / `Authorization` header still gates display. **HealthStatusProvider single-poll guarantee must be preserved** — the gate change alters tab visibility, not the underlying provider context, so HealthBanner (which is intentionally NOT gated) and the merged tab still consume from one provider instance and `/api/health` polls once per cycle.
- **D-27: Rename to "API Health"; first position in tab bar.** Final tab order: **API Health** / Water / Sites / Events. Names matches the `/api/health` endpoint and frames the panel around what the operator cares about during incident triage. The modal title `API Status` (`DevApiStatus.tsx:816`) stays unchanged.
- **D-28: New dedicated wave (W5) for the merge + four diagnostic blocks; W6 for the prod audit.** Independent from W1–W4 (dev/prod promotion, Bearer-gating, domain rename, rate-limiter). Cleaner commit train, easier per-commit rollback, and W6 audit gates phase close. **Wave gate sequence:** W1–W4 land first (any order Claude decides), W5 lands the dashboard merge with the diagnostic blocks, W6 runs the connectivity audit against the deployed prod URL — passing W6 is the phase-close trigger.
- **D-29: Smoke suite uses `API_BASE_URL` env var, default `http://localhost:5173`.** Same vitest suite runs locally during dev (defaults to localhost) and against prod (`API_BASE_URL=https://otg-iran-monitor.vercel.app`). Mirrors the `scripts/load-test.js` BASE_URL pattern (which itself updates per D-03). The CI workflow that runs the W6 prod audit sets `API_BASE_URL` from a GitHub Actions secret/env so the URL is not hardcoded into the test source. Single-suite, two-environment.
- **D-30: Audit runs WITH Bearer always.** The connectivity audit (manual + vitest) attaches the `DASHBOARD_PASSWORD` Bearer to every request. This (a) bypasses D-04's global 6 req/min rate limit so the suite hits all 16 endpoints in seconds without 429s, and (b) validates that D-04 Bearer-bypass actually works end-to-end. **Explicit companion test:** a separate `rate-limit.test.ts` sends one unauthenticated burst over 60s, asserts that ≥1 request returns 429 — captures the public-throttle-still-defends regression. So the audit covers connectivity and the companion test covers the rate-limit contract, in two passes not bundled.
