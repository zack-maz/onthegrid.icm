<objective>
Per CONTEXT D-08 + AI-SPEC §6: re-affirm Bearer-gating on `POST /api/events/llm-pipeline` and `POST /api/events/llm-replay/:groupKey` (already gated since Phase 27.4.4 Plan 02 — this plan adds the new operator-control hardening on top). Two new server-side guardrails:

1. **Per-Bearer replay quota** (AI-SPEC §6 / UI-SPEC §6.2) — 50 `/llm-replay` calls per 24h rolling window per Bearer fingerprint. At cap, returns HTTP 429 with `Retry-After` so a compromised Bearer cannot exhaust the daily token budget within minutes. Implementation: Redis `INCR operator:replay-quota:{fingerprint}:{YYYY-MM-DD}` with 48h TTL on first set, ~6 lines of route-handler logic per AI-SPEC scope-constraint guidance ("cheaper than rate-limiter middleware extension").

2. **Operator-action audit log** (AI-SPEC §5 / §6 / §7) — every successful pipeline-swap or replay writes a structured Redis SADD entry containing `{timestamp, bearerFingerprint, operation, args, result}`. Synchronous before HTTP response. Bounded 500 entries, 30d TTL, eviction via SCARD-check + raw-string SREM. Powers the AI-SPEC §7 monitoring surface (Operator Actions block in Plan 05's merged API Health tab) — this plan creates the helper + writes; Plan 05 surfaces the reads.

3. **Adversarial sub-eval (B-2 server side)** (AI-SPEC §5 + §7) — ~10-entry prompt-injection fixture at `.planning/eval/adversarial-injections.json` exercises the same `resolveLocation` / extractor path used by `/llm-replay` to verify schema-strictness + non-leakage of injection content. New `runAdversarialEval()` exported from `server/lib/llmEvalHarness.ts` returns `{total, blocked, leaked, score: blocked/total}` and persists to `events:llm-eval-adversarial:v3` (90d TTL, mirrors existing `events:llm-eval-baseline:v3` pattern). Folded into `server/routes/cron-health.ts` AFTER the existing `runEval()` call so the daily cron tick produces both accuracy + robustness scores in one pass (no new cron entry — Hobby cap preserved). The merged tab in Plan 05 reads this Redis key to render the `Prompt-injection robustness: N/N` row in the eval-score block.

**Pitfall 6 dual-gate is preserved.** Per CLAUDE.md "V2 Extractor Watchdog (Phase 27.4.1)" + AI-SPEC §6: the `/llm-replay` route NEVER writes `events:llm:v3` terminal cache — it returns `{old, new}` diff only. Per checker W-5, primary verification is now a **Redis-snapshot byte-identity test** (read `events:llm:v3` before + after a `/llm-replay` request; assert `after === before`), with the existing grep `! grep -n 'cacheSet.*events:llm:v3' server/routes/events.ts` retained as secondary defense-in-depth.
