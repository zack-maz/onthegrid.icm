## Trust Boundaries

| Boundary                               | Description                                                                                      |
| -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| anonymous client → /api/\*             | untrusted traffic the rate limiter sheds; the 429 counter sits on this already-error path        |
| operator Bearer → /api/operator-status | privileged read of limiter config + 429 counts; must stay behind the existing dashboardAuth gate |
| middleware → Upstash Redis             | degrade-open boundary — a Redis failure on the counter must not affect the 429 response          |

## STRIDE Threat Register

| Threat ID  | Category               | Component                                                              | Disposition | Mitigation Plan                                                                                                                                                                       |
| ---------- | ---------------------- | ---------------------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-46-01-01 | Denial of Service      | 429 INCR on the hot error path (rateLimit.ts)                          | mitigate    | Fire-and-forget `void incr429(tier)` fully wrapped in try/catch; the 429 response sends regardless; explicit test asserts a throwing INCR stays a 429, never a 500 (D-02 / Pitfall 3) |
| T-46-01-02 | Denial of Service      | `ratelimit:429:*` Redis-write amplification                            | mitigate    | Per-tier per-day key (1 EXPIRE per tier per day), self-expiring 48h TTL; you can only INCR while already being 429'd (bounded by the limiter itself)                                  |
| T-46-01-03 | Information Disclosure | rateLimiter block exposes limit config + 429 counts                    | accept      | Operator-tier metadata, non-secret; stays behind the existing `dashboardAuth` Bearer gate on /api/operator-status — not moved to an un-gated route (ASVS V4)                          |
| T-46-01-04 | Elevation of Privilege | Bearer bypass blast radius (operator Bearer drains a per-route budget) | accept      | Pre-existing W6 audit decision (rateLimit.ts:53-73); D-03 only PROVES the bypass reaches every tier, it does not widen the radius                                                     |
| T-46-01-05 | Tampering              | `ratelimit:429` key components (tier, date)                            | mitigate    | Both key components are server-derived (tier name from `rateLimiters`, date from `new Date()`); no client-controlled input in the key — no injection surface (ASVS V5)                |
