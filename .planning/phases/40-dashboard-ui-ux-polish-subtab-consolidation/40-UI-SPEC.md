## Typography

Carried forward from the existing operator-console idiom (28.2-UI-SPEC §8, 39-UI-SPEC §Typography) and made into a **real hierarchy** per D-03 (the fix: not everything at 9–10px). Four roles, two weights.

| Role         | Size | Weight         | Line Height | Tailwind                                                                 | Usage                                                                                                               |
| ------------ | ---- | -------------- | ----------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| Hero metric  | 13px | 600 (semibold) | 1.2         | `text-[13px] font-semibold` + `tabular-nums`                             | The 4–5 hero-strip headline values (N/M healthy, budget %, dead-URL count)                                          |
| Group header | 11px | 700 (bold)     | 1.3         | `text-[11px] font-bold uppercase tracking-wider`                         | The 4 collapsible section titles (Endpoint Health / LLM Pipeline / Budget & Cost / Operator Actions & Data Quality) |
| Label        | 10px | 600 (semibold) | 1.4         | `text-[10px] font-semibold` (table headers: `font-normal text-white/40`) | Field labels, table column heads, drill-down captions, drawer item labels                                           |
| Value / body | 10px | 400 (regular)  | 1.4         | `text-[10px]` + `tabular-nums` on numerics                               | All metric values, run/call rows, USD/token numbers, per-endpoint cells                                             |

**Two weights only:** regular (400) + semibold (600), with bold (700) reserved for the group headers (the one place the hierarchy needs maximum separation). `tabular-nums` is MANDATORY on every numeric (counts, %, ms, USD, freshness) so values don't jitter on the 2s tick / 30s poll.

**Hierarchy rule (D-03 — the load-bearing change):** the prior surface ran the tier banner, table cells, LLM section, and operator-actions rows all at `text-[9px]`/`text-[10px]` with no header distinction. The post-polish surface establishes **three visible tiers**: hero metric (13px/600) ≫ group header (11px/700 uppercase) ≫ label+value (10px). The `text-[9px]` size is RETIRED for structural text — it survives ONLY inside the JSON `<pre>` dumps and the truncated-list "… and N more" micro-rows.

### NEW semantic tokens (3 — D-04 + D-13 single-source contract)

The hero header (D-05) and the unified status dots need named **status** semantics distinct from the entity `--color-*` map palette. Today the tier banner borrows `--color-site-healthy` / `--color-site-attacked` / `--color-event-airstrike` (map tokens) as status colors — semantically wrong and a drift risk. This phase adds 3 purpose-named tokens and migrates the operator-console status dots/sparkline onto them.

| Token (`app.css @theme`)  | Hex       | Maps to                                                                                 | Tailwind utility                              | Used by                                                                      |
| ------------------------- | --------- | --------------------------------------------------------------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------- |

| `--color-status-degraded` | `#f97316` | (same orange as `--color-site-attacked`)                                                | `text-status-degraded` / `bg-status-degraded` | Hero degraded indicator; tier-summary degraded dot; budget soft-band context |
| `--color-status-warning`  | `#eab308` | (amber/yellow — matches budget soft-tick semantics)                                     | `text-status-warning` / `bg-status-warning`   | Hero budget-soft-proximity indicator; "approaching cap" context              |

**Hex (NOT OKLCH)** so `colorBridge.ts`'s hex parser roundtrips cleanly, consistent with the existing entity-token format (app.css :44 comment). **Routing (D-13 — MANDATORY):**

1. Declare each in `src/styles/app.css @theme` (hex).
2. Add a `readCssHex(...)` re-export in `src/lib/colorBridge.ts` (`COLOR_STATUS_HEALTHY_HEX`, `COLOR_STATUS_DEGRADED_HEX`, `COLOR_STATUS_WARNING_HEX`) with the byte-identical fallback default.
3. Add the matching fallback-default assertion to the byte-identity sentinel `src/__tests__/lib/colorBridge.test.ts` (the test FAILS the build if a fallback drifts).

> **Migration note (planner):** the sparkline (`:1204`), tier-summary banner (`:1314`, `:1322`, `:1330`), keep their CURRENT runtime colors — only the **token name** changes (`var(--color-site-healthy)` → `var(--color-status-healthy)`, etc.). Because the new hex is byte-identical, this is a zero-visual-change rename that gives the operator surface its own status namespace. RGBA tuple re-exports are NOT needed (no deck.gl consumer); hex re-exports only.

## Degraded-State Convention (D-06) — honest, never self-hiding

The **4 top-level GROUPS and the hero header ALWAYS render.** On null / stale / missing data they show a **muted placeholder** rather than vanishing. Degrade-open semantics are otherwise preserved: route stays 200, block never throws — this changes ONLY the empty render, not the error contract.

### Muted placeholder pattern (markup + token)

```jsx
<div className="text-[10px] text-white/30 italic" data-testid="{block}-placeholder">
  — no data ({reason})
</div>
```

- Token: **`text-white/30`** (the muted ramp step, dimmer than the `text-white/40` label step) + `italic` to read as intentional-absence, not a value.
- Copy form: `— no data ({reason})` where `{reason}` is the specific cause (e.g. "no health data", "no budget data yet", "operator-status unreachable", "no runs recorded").

| Group 2 LLMPipelineSection        | renders                                           | KEEP                                                                                                                                                                       |
| Group 2 FlightRecorderBlock       | **self-hides on non-200** (:1765 contract)        | CHANGE → muted placeholder `— no data (no runs recorded / recorder unreachable)`; the GROUP stays                                                                          |
