# Phase 28.2.7 Plan 02: llm:lastProgress write-through + Redis-first probe Summary

**Redis-backed write-through in `llmProgress` setters + async Redis-first `probeLlmStatus()` with in-memory singleton fallback, solving the Vercel Fluid Compute cold-start blocker on `non-critical[llmStatus]: unknown`.**

## Performance

- **Duration:** ~5 min

- **Completed:** 2026-05-08T04:42:12Z
- **Tasks:** 3
- **Files modified:** 2 source + 1 new test file

## Accomplishments

- `LLM_LASTPROGRESS_KEY = 'llm:lastProgress'` and `LLM_LASTPROGRESS_TTL_SEC = 7 * 24 * 60 * 60` (604_800) added to `server/lib/llmProgress.ts`, co-located with `INITIAL_PROGRESS` + the singleton + the setters per CONTEXT D-07.
- `resetProgress()` and `updateProgress()` now write through to Redis via `void cacheSetSafe(...)`. resetProgress writes unconditionally (D-01 — fires on every `startedAt`-set transition). updateProgress writes only when `partial.completedAt !== undefined` (D-02 — terminal-only, mid-run batch updates skip). Result: ~2 Redis writes per pipeline run (1 reset + 1 done), not ~50-200.
- `probeLlmStatus()` refactored from sync to async, Redis-first with in-memory singleton fallback (D-08). The Vercel Fluid Compute cold-start problem — where a fresh function instance saw `INITIAL_PROGRESS` and emitted `freshnessMs: null → 'unknown'` regardless of whether the most recent cron actually ran — is solved. A fresh instance now reads the prior run's `{startedAt, completedAt}` from Redis and emits `freshnessMs !== null → 'healthy'`.
- D-09 fresh-deploy bias preserved: BOTH Redis null AND singleton at `INITIAL_PROGRESS` → `freshnessMs: null → 'unknown'`. First cron tick within 26h flips the tier green.
- D-10 read-only probe invariant: probe body contains zero `llmProgress.<field> =` assignments. Singleton becomes eventually consistent via the next pipeline's `resetProgress` call.
- Degrade-open per Phase 28.1 W2: cacheGetSafe throws or times out → try/catch in the probe falls through to the in-memory singleton. Test 7 asserts this end-to-end via `cacheGetSpy.mockImplementationOnce(throw)`.
- 7 contract tests in `server/__tests__/lib/llmProgress.persistence.test.ts`: 3 write-through cases (D-01 + D-02 mid-run skip + D-02 terminal write) + 4 probe cases (D-08 SPEC R2 acceptance + D-09 both-null + 2 degrade-open paths).
- Full vitest suite: **2187 passed** (baseline 2180 + 7 new), 19 skipped, 5 todo. `tsc --noEmit` exits 0. Zero regressions.
