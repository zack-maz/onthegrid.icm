## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Added scripts/bakeoff-v3-direct.ts as a circuit-breaker-bypass companion to scripts/bakeoff-v3.ts**
- **Found during:** Task 2 (Run bake-off iterations) — first executor's first-pass run
- **Issue:** The plan's Task 2 prescribed a single harness that exercises `LLM_PIPELINE_V3=true V3_BAKEOFF_MODEL=<id> /api/events?force=true` end-to-end through freeClaudeRouter. In practice, freeClaudeRouter's per-Provider circuit breaker treats `nvidia_nim` as a single Provider regardless of which model is being requested — once one bake-off candidate (z-ai/glm4.7) tripped the breaker, all subsequent candidates received `nvidia_nim:skipped:breaker` decisions and produced 0 LLM calls (false negatives in the matrix).
- **Fix:** Added scripts/bakeoff-v3-direct.ts which calls NVIDIA NIM via the OpenAI SDK directly (no freeClaudeRouter cascade), with maxRetries=0 + 60s AbortController hard cap + early-abort after 3 consecutive hard fails. Per-model evaluations are now independent. The breaker is correct production behavior; only the bake-off harness needs the bypass. Both harnesses are committed so Phase 27.5+ has both tools available.
- **Files modified:** scripts/bakeoff-v3-direct.ts (new, 372 lines)
- **Verification:** Direct harness produced clean per-model scores for all 7 candidates (no `breaker` skip-entries in the matrix); BAKEOFF.md anomalies section documents the contamination bug + bypass rationale.
- **Committed in:** `061055e` (Task 2 commit, alongside the original bakeoff-v3.ts)

**2. [Rule 1 — Bug] Returned `'moonshotai/kimi-k2.5'` as the placeholder default in Task 1, even though it was already known to be a deferral candidate**
- **Found during:** Task 5 (Winner lock)
- **Issue:** Task 1's V3_PRIMARY_MODEL plumbing kept the existing `'moonshotai/kimi-k2.5'` literal as the fallback. After Tasks 2-3 established that kimi-k2.5 was deferred (latency unfit), leaving it as the production fallback would have been a Rule 1 bug — every freeClaudeRouter call without V3_PRIMARY_MODEL set would have routed to a model the bake-off explicitly rejected.
- **Fix:** Task 5's commit (28f1c0b) updates the literal to `'qwen/qwen3.5-397b-a17b'` (the BAKEOFF winner) with a multi-line operator-approval audit comment block referencing the matrix file, the floor cleared, the runner-up identity, and the re-evaluation command. Self-contained explanation for future maintainers.

## Issues Encountered

- **Circuit-breaker contamination across models in the router-mediated harness** (documented above as Deviation 1 + in BAKEOFF.md anomalies). Resolved via the direct SDK harness companion. Production behavior is unaffected — the breaker correctly treats nvidia_nim as a single Provider.
- **Resolver-only `runEval()` baselines all return `47/50` (0.940) for ALL candidates** — this is by design (resolver scores hierarchies, not LLM output) per CONTEXT A6 / Pitfall 8. The discriminator is the end-to-end LLM-emit → Zod → resolveLocation → haversine path which the bake-off harness exercises directly. Documented in BAKEOFF.md anomalies so a future maintainer doesn't mistake the equal-baseline behavior for harness drift.
- **Many bake-off rows show `gdelt-actiongeo-fallback` provenance with dist=0.0km** — because the harness feeds `centroidLat: ev.truth.lat, centroidLng: ev.truth.lng` to resolveLocation (mirroring how runEval ground-truths the centroid). When the LLM hierarchy doesn't trigger a Nominatim resolve, branch 6 falls through to the centroid — which is the truth itself. This is consistent with the production runEval pattern; absolute distances on the bake-off are conservative, the relative ordering across models is the discriminator. Documented in BAKEOFF.md anomalies.
- **OPENROUTER_API_KEY not set in this dev environment** — all routing decisions show `openrouter:fall_through:nvidia_nim_no_client` when the cascade falls through. For Plan 05 production cutover, OpenRouter as a fallback is optional per D-09; without it, v3 gracefully degrades to raw GDELT on NVIDIA NIM exhaust (the existing D-29 contract). Documented in BAKEOFF.md anomalies.
