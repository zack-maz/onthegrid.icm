>

The governing rule is **match the existing `DevApiStatus.tsx` block idiom exactly** — no net-new visual language. ## Spacing Scale

The existing block idiom uses a **tight, Tailwind-default 4px-base scale** (this is a dense diagnostic panel, not a marketing surface). Declared values in use, all multiples of 4 (Tailwind's `0.5 = 2px` half-step is the one documented exception, used for sub-row gaps):

| Token         | Value        | Tailwind class          | Usage in this surface                                              |
| ------------- | ------------ | ----------------------- | ------------------------------------------------------------------ |
| block-top     | 8px          | `mt-2`                  | Gap between stacked blocks (every block opens with `mt-2`)         |
| row-top       | 4px          | `mt-1`                  | Gap between a block header and its first row                       |
| separator-pad | 8px          | `pt-2`                  | Padding below the `border-t` separator that opens v3-native blocks |
| inline-gap    | 4px          | `gap-1`                 | Horizontal gap between glyph + label + value in a row              |
| pill-pad-x    | 4px          | `px-1`                  | Status-pill / reason-chip horizontal padding                       |
| scroll-cap    | 80px / 128px | `max-h-20` / `max-h-32` | Max height of scrollable row lists before `overflow-y-auto`        |

Exceptions:

- **`mt-0.5` (2px)** — sub-row spacing inside list blocks (e.g. `HistogramsBlock` per-provenance rows at `DevApiStatus.tsx:2601`). Tailwind half-step; permitted because it is the established idiom for nested list density. Do NOT introduce any new fractional steps beyond `0.5`.
- **No `lg`/`xl`/`2xl`/`3xl` layout spacing** applies — this surface lives entirely _inside_ the existing `role="tabpanel"` container and adds no layout-level structure (D-12: tablist/panel DOM is frozen).

## Typography

This surface has exactly **one body size** plus the inherited panel chrome. Do NOT introduce new sizes — the restyle phase (45) owns any hierarchy changes.

| Role                      | Size | Weight        | Line Height | Class / source                                                                                                            |
| ------------------------- | ---- | ------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------- |
| Block header              | 9px  | bold (700)    | normal      | `text-[9px] font-bold uppercase tracking-wider text-white/40` (universal block-title idiom, e.g. `DevApiStatus.tsx:2558`) |
| Body / row text           | 9px  | regular (400) | normal      | `text-[9px]` (every row, value, label)                                                                                    |
| Sub-percent / micro-label | 8px  | regular (400) | normal      | `text-[8px] text-white/40` (ProgressBar percent only, `DevApiStatus.tsx:120`) — pre-existing, do not extend               |

- **Sizes in this phase: 2 effective** (9px body, 8px micro) — under the 3–4 ceiling. The 8px is pre-existing and confined to the shared `ProgressBar`; `DeadLinkBucketsBlock` uses **9px only**.
- **Weights: 2** — regular (400) for content, bold (700) for the uppercase block header. No semibold/medium in block bodies.
- **Tracking:** `tracking-wider` is mandatory on every uppercase block header and status pill (existing idiom).
- **Case:** block headers and status pills are `uppercase`; row content is sentence/literal case.

## Color

This is a **dark operator panel**: black/translucent surface, white-with-opacity text. The "60/30/10" split maps onto the existing opacity ladder, not distinct hues.

| Role              | Value                                                                               | Usage                                                                 |
| ----------------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Dominant (60%)    | `bg-black/85` (panel) + `text-white/60` (default row text)                          | Panel surface + body content                                          |
| Secondary (30%)   | `text-white/40` (headers, muted labels, "no data") + `border-white/10` (separators) | Block headers, muted/empty states, hairline separators                |
| Accent (10%)      | `text-white/80` (emphasized values)                                                 | Highlighted numeric values within a row (e.g. success-rate numerator) |
| Semantic — danger | `text-red-400` / `bg-red-500/20 text-red-300` (chip) / `●` red bullet               | Dead/error states: DLQ header, terminal-dead status badges            |
| Semantic — warn   | `text-amber-400` / `bg-amber-500/20 text-amber-300` (chip)                          | Suspect counts > 0, `unknown` status, cascade-fallthrough reasons     |
| Semantic — ok     | `text-green-300` / `bg-green-500/20 text-green-300` (chip)                          | `live` status, `primary` routing reason                               |

**Accent reserved for:** emphasized numeric values inside a row (`text-white/80`) and the three semantic states (red = dead/error, amber = suspect/unknown/degraded, green = live/healthy). Accent is **never** applied to whole rows, headers, or as a generic "interactive" affordance. Status color is driven by the liveness status value, not by interaction state.

**`DeadLinkBucketsBlock` status → color map (mirror the existing semantic ladder — the server comment at `operator-status.ts` pins "Phase 44 renders the badge color off this field"):**

| Liveness status                          | Color treatment                                               |
| ---------------------------------------- | ------------------------------------------------------------- |
| `live`                                   | green (`text-green-300` / green chip)                         |
| `unknown`                                | amber (`text-amber-300`)                                      |
| `no-url`                                 | muted (`text-white/40`) — not a failure, just no URL to probe |
| `404` / `403` / `dead-host` / `soft-404` | red (`text-red-300` / red chip) — terminal-dead family        |

Reuse the existing `STATUS_PILL_CLASSES`-style chip idiom (`rounded px-1 text-[9px] font-bold uppercase tracking-wider`, `DevApiStatus.tsx:1784`) for per-status badges. Do NOT author a new chip component.

## Copywriting Contract

No CTAs and no destructive actions in this phase — every surface is **read-only telemetry**. The "copy" contract is therefore about **empty/hidden states** and **honest labels** (degrade-open is the central UX requirement, SC-3).

| Element                                                                    | Copy                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Primary CTA                                                                | none — read-only surface (no buttons except the pre-existing, untouched `DrillDownRow` "Copy prompt+response" replay button, which this phase does not modify)                                                                                                                                                                                                                                                                                            |
| Empty state — block with no data                                           | Block **self-hides** entirely (presence-gated, D-05). Do NOT render a synthetic zero or an empty shell. Exception: blocks whose existing idiom renders an inline muted line MAY keep it — `DlqBlock` → `DLQ: 0 entries`; `SuspectBlock` → `Suspect events: 0`; `HistogramsBlock` inner → `no data`. Match each block's existing empty copy verbatim; do not invent new copy.                                                                              |
| Empty state — `DeadLinkBucketsBlock` when `prune` absent                   | Block **self-hides** (degrade-open: older server, fetch failure, missing Bearer). No placeholder.                                                                                                                                                                                                                                                                                                                                                         |
| Empty state — `DeadLinkBucketsBlock` when `prune` present but no dead URLs | `Dead URL events: 0` (mirror the existing `opStatus.prune.deadUrlCount` line at `DevApiStatus.tsx:1985`); the per-bucket tally and sample rows render only when non-empty.                                                                                                                                                                                                                                                                                |
| Sampled-tally caveat (D-03)                                                | Per-status bucket counts MUST be labeled as sampled, e.g. `of N scanned` (where N ≤ 200, the `MAX_SCAN_KEYS` budget). Suggested wording: header `By status (sampled — N of cap 200 scanned)` or a trailing `· of N scanned` per the existing "X of Y" idiom (`DevApiStatus.tsx:1435/1442`). The authoritative terminal-dead total is the separate `Dead URL events: {deadUrlCount}` line; **never** present the sampled tally as the authoritative total. |
| attemptCount label (D-02)                                                  | Render `attemptCount` as dead-streak depth, not as an event count. Suggested: `dead ×N` or `N consecutive sweeps` (one sweep ≈ one day under the daily cron). Pair with `lastProbedAt` rendered via the existing `relativeTime()` helper (`DevApiStatus.tsx:72`) → e.g. `probed 4h ago`.                                                                                                                                                                  |
| `evidence` rendering (D-11 / T-43-16)                                      | Render as **plain TEXT** (React text-node, default-escaped). **NEVER** `dangerouslySetInnerHTML`. Server caps `evidence` at ≤200 chars (Phase 43 D-16); truncate with the existing `truncate` class if a row overflows.                                                                                                                                                                                                                                   |
| Error state                                                                | No error UI — fetch failures degrade open (block self-hides). Consistent with the whole panel's degrade-open contract.                                                                                                                                                                                                                                                                                                                                    |
| Destructive confirmation                                                   | none — no destructive actions in this phase                                                                                                                                                                                                                                                                                                                                                                                                               |

**Honest-label rules (load-bearing — these ARE the UX contract for this phase):**

- Never fabricate `cerebras:0 / groq:0` zeros for purged providers (D-05/D-06). `BudgetBarsBlock` self-hiding under NIM-only is **correct**, not a defect.
- Never present the sampled `countsByStatus` as the authoritative dead total (D-03).
- Never render `evidence` or URL strings as HTML (D-11).
- Never imply a true "first-seen-dead" timestamp — only `lastProbedAt` + `attemptCount` exist (D-02).

**`DeadLinkBucketsBlock` internal layout (D-09, follow the `DlqBlock`/`RoutingTraceBlock` two-tier idiom):**

1. Header: `text-[9px] font-bold uppercase tracking-wider text-white/40` → `Dead Links`.
2. Authoritative total row: `Dead URL events: {deadUrlCount}` + `last24hPrunes` (e.g. `· pruned 3 in 24h`).
3. Per-status bucket rows (`countsByStatus`): one row per status, status badge (semantic color) + count + `of N scanned` caveat (D-03).
4. Sample drill-down rows (`deadUrlSample`, ≤20): each row = status badge · truncated `url` · `evidence` (TEXT) · `relativeTime(lastProbedAt)` · `dead ×attemptCount`. Wrap long lists in `max-h-32 overflow-y-auto` per existing idiom.
