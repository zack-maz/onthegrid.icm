<objective>
Extend the read-only `/api/operator-status` aggregator so the events subtab (Plan 02) can render per-liveness-status bucket counts and richer drill-down rows, then lock the change across all three contract surfaces in the same commit.

This is the locked D-01 minimal server extension: tally `countsByStatus` across all statuses inside the EXISTING `buildDeadUrlSample` SCAN loop (no extra Redis reads), and add `lastProbedAt` + `attemptCount` to each `DeadUrlSampleEntry` (both already exist on the stored `UrlLiveness` value). While editing the prune schema, ALSO close the pre-existing Phase 43 OpenAPI drift (the spec is missing `evidence` and the `soft-404` enum member the code already emits).

Purpose: EVENTS-TAB-02 success criterion 2 requires per-liveness-status counts plus transition timestamps that the aggregator does not expose today. D-01 interprets the roadmap "no server changes" gloss as "no new Redis keys, no new writers, no pipeline changes" — which this honors exactly.
Output: A wider prune block + lockstep route test + OpenAPI schema sync + client forward-compat interface. No new Redis keys, no writers, no pipeline behavior changes.
</objective>
