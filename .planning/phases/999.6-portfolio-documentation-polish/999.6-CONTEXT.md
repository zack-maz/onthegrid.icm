# Phase 999.6: Portfolio Documentation Polish — Context (BACKLOG)

**Captured:** 2026-06-03 (at v1.5 close)
**Status:** Backlog — promote at v1.6 or later via `/gsd-review-backlog`
**Parent:** None — standalone portfolio-targeted phase
**Branch discipline:** Per `feedback_branch_per_phase.md`, this phase will get its own feature branch on promotion.

## Goal

Round out the **agentic-development portfolio surface** of Iran Monitor for the v1.6 reveal. Not commercial polish — first-portfolio-piece polish: tell the story of how the project was built with Claude Code, make the engineering depth navigable for outside readers, and humanize the product arc from "I want to track Iran conflict events" → "10 phases of LLM reliability." The existing surface (564-line README + 11 ADRs + 12 architecture docs + 21 Mermaid diagrams + 676-line SRE runbook + degradation contract) is strong; this phase fills the **agentic-dev meta-story** + **navigation hub** + **glossary** + **transparency** gaps.

## Why now (v1.6 backlog, not v1.5 close)

Phase 36 (Public Docs Sweep, closed 2026-05-30) covered the **technical** docs surface (README + architecture + runbook + degradation + OpenAPI). It did NOT cover the **narrative + agentic-dev meta + portfolio-tour** surfaces, because those weren't in v1.5 scope (DOCS-PUB-01..05 + DOCS-API-01..07 were all technical). Promoting these to v1.6 makes sense alongside REVEAL-01 + REVEAL-02 (public reveal polish) since they share the audience — portfolio visitors, not operators.

## Audience

- **Primary:** portfolio visitors (engineers, hiring managers, fellow agentic-dev practitioners) browsing the GitHub repo for the first time.
- **Secondary:** the operator (you) — better cross-linking + onboarding from a future "I haven't touched this in 6 months" return visit.
- **Tertiary:** fellow agentic-dev practitioners curious about the GSD workflow + Claude Code usage shape.

**Audience NON-goals:** commercial customers (no commercial intent); enterprise SREs (the existing runbook covers operational depth).

## Scope (10 deliverables)

The 10 doc surfaces grouped by impact:

### Top-3 (highest signal for agentic-dev portfolio)

1. **`docs/BUILDING-WITH-CLAUDE-CODE.md`** — the meta-story. The killer differentiator. Cover: what the `/gsd` workflow is, what a phase looks like (CONTEXT → DISCUSSION → PLAN → EXECUTE → VERIFY), where compounding worked (mechanical drift gates, parallel agents, probe-before-commit), where it didn't (Phase 26.2 NLP scrap = 2 weeks committed then deleted; Phase 31 closed early at Day 1/7 with caveat that surfaced 23 days later; Phase 34 honest deferral; Phase 37 architectural-mismatch unblocker PRs), cost observations (phases-per-week, Claude Code session shape, what the agents are good at vs. what still needs human judgment). Synthesize from `.planning/RETROSPECTIVE.md` + MILESTONES.md + phase 37-SUMMARY framing-gap callouts. Target ~600-1000 lines portfolio-readable prose. **This is the single biggest move.**

2. **`docs/SHOWCASE.md` (or `docs/portfolio/INDEX.md`)** — the guided tour. A 1-page hub for portfolio visitors. "Start with the hero GIF" → "Want decisions? Read ADR-0005 (NLP scrap) + ADR-0010 (v1.5 close)" → "Want architecture? Start with `system-context.md`" → "Want operations? Read the runbook" → "Want how it was built? Read BUILDING-WITH-CLAUDE-CODE.md" → "Want the codebase? Start with `src/components/map/BaseMap.tsx`." Without this hub, engineering depth is invisible from outside the repo.

3. **`docs/JOURNEY.md`** — the product arc narrative. Portfolio-readable from "March 13, 2026: I want to track Iran conflict events" → "June 3, 2026: shipped 10 phases of LLM reliability" with the WHY for each milestone (v0.9 = "can I even render a map?" → v1.5 = "is the LLM pipeline actually reliable?"). Synthesizes `.planning/RETROSPECTIVE.md` into something a non-engineer can read. Includes a Mermaid gantt of the 7 milestones over ~3 months.

### Round-out (4-6)

4. **`docs/concepts.md`** — glossary. ~30 proprietary terms defined: **Pitfall 1 cache bridge**, **LLM-optional architecture**, **tier-green gate**, **polite-citizen contracts**, **ghost event**, **canonical actor catalog**, **mechanical drift gate**, **degrade-open**, **6-path resolver**, **honest deferral**, **probe-before-commit**, etc. Lowers the bar for any visitor to read the architecture docs.

5. **`docs/COSTS.md`** — transparency. Honest accounting: Vercel Pro $20/mo, NIM free, Upstash free tier, GDELT/OpenSky/adsb.lol/Open-Meteo/Yahoo Finance/AISStream/Overpass/WRI/Natural Earth/GeoEPR all free, Claude Code costs for development (session count, model mix, approximate cost per phase). The "you can do this too" angle. Portfolio-relevant.

6. **`docs/operator-guide.md`** — how-to. Different from runbook (incident response). "You're a visitor, here's what you can do":
   - Clone + run locally (`npm install`, `.env.example` setup)
   - Force-trigger the cron (`?force=true` + Bearer)
   - Prune dead URLs from the dashboard
   - Read the `/api/operator-status` payload
   - Run the eval harness (`npm run eval:replay`)
   - Capture a fresh hero GIF (`npm run capture:hero`)

### Vercel Pro cleanup-and-repair (11)

11. **Vercel Pro code + docs reconciliation.** Phase 29 upgraded the project to Vercel Pro ($20/mo) with `maxDuration: 300 → 800` but only the single load-bearing change shipped. Many surfaces still claim Hobby-era semantics OR don't take advantage of Pro features the project is now paying for. Audit + repair across both code AND docs:

    **Code surfaces to verify / repair:**
    - **`vercel.json`** — `maxDuration: 800` confirmed in place; cron entries currently 3 (could grow to 4 with a `news:feed` warmer per v1.6 punch-list finding #15; Pro cap is 40, not the still-cited Hobby "3").
    - **Migration from `vercel.json` → `vercel.ts`** — per recent Vercel knowledge update, `vercel.ts` is the recommended project-configuration format (install `@vercel/config`; full TypeScript support, dynamic logic, env-var access at config time). Evaluate whether the migration is worth the lift; ship if it lets us delete config drift handlers elsewhere.
    - **`api/vercel-entry.js`** — 1.7 MB tsup-bundled function tracked in git (Phase 999.2 backlog item). Pro tier supports Vercel Build Output API (`.vercel/output/functions/api/vercel-entry.func/`) which would let us drop the tracked artifact entirely. 999.2 may close as part of this work.
    - **`s-maxage` CDN headers on `/api/*`** — Phase 999.5 Performance Load Test D-19 prescribes per-endpoint TTLs (flights 5s, ships 30s, markets 60s, events/news 900s, sites/water 86400s). If 999.5 lands first this is moot; if 999.5 hasn't landed yet, ensure the Pro tier's Vercel CDN can actually absorb the bulk reads + Redis only fires on miss + warm-up cron.
    - **Fluid Compute** — per recent Vercel knowledge update, Fluid Compute is now the default and supports request reuse / graceful shutdown / request cancellation. Verify the Express app via `createApp()` factory in `server/app.ts` is compatible (it should be; Fluid runs regular Node.js).
    - **Vercel CLI version** — session-start diagnostics showed CLI 52.0.0 vs latest 54.7.1. Operator-facing tooling — bump in the dev environment.
    - **`server/lib/llmTokenBudget.ts` cost-shadow accrual** (`events:llm-cost-shadow:v3:{YYYY-MM-DD}`) — confirm the USD microcents conversion (×1e6) still matches NIM's published per-token rates; cost transparency rides on this number.

    **Doc surfaces to repair (overlap with [[project-v1-6-docs-drift]]):**
    - `CLAUDE.md:101` — "Hobby cap 3 entries" stale framing (drift audit finding #13).
    - `docs/architecture/deployment.md:56` — "Hobby tier's 60 s ceiling" wrong (drift finding #14a).
    - `docs/architecture/deployment.md:133` — "Vercel Hobby/Pro tier caps at 3 cron entries" wrong (Pro = 40; drift finding #14b).
    - `docs/runbook.md:539-547` — §9 still references "10-second limit" (drift finding #15).
