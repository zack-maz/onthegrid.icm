## Retired Mechanisms

### SIMPLIFY-01 — Incremental flush (Phase 28.2.6 → retired Phase 30)

**What it was:** `mergeAndPersistLlmEntities` was called from the `onBatchComplete` callback in `server/lib/llmExtractionPipeline.ts` every N batches (`LLM_FLUSH_EVERY_N_BATCHES`, default 10). This wrote `events:llm:v3` partial state mid-run as a Hobby-era guard against 300s hard kills truncating the run before the terminal write.

**Why retired:** Pro 800s `maxDuration` (Phase 29 D-08) makes the terminal end-of-run write the canonical shape. The mid-run writes were duplicating data and inflating Redis SET-call count.

**Audit signal:** Redis `events:llm:v3` SET-call count per cron run dropped from `N` (pre-Plan-03) to **1** (post-Plan-03). Exact delta captured in `feat(30): retire incremental flush mechanism` commit body.

**What stays:** the `mergeAndPersistLlmEntities` helper itself (called once at end-of-run, `server/lib/llmExtractionPipeline.ts:477`). `events:llm:v3:partial` observability key stays (owned by SIMPLIFY-02 in Phase 34).

### SIMPLIFY-03 — Watchdog soft-warn tier (Phase 28.2.5 → eliminated Phase 30)

**What it was:** `withBatchWatchdog` had two tiers: 60s soft-warn (log + synthetic `callHistory` `skipReason: 'soft_warn_*'` entry) and 90s hard-kill (AbortController). The soft-warn predated NIM and was tuned for Cerebras's intermittent slowness under high traffic.

**Why eliminated (not relaxed):** Cerebras was retired Phase 29 D-01. At Run-1 measured p50 batch latency (~PASTE_VALUE ms), a 60s soft-warn fires too rarely to carry signal. The historical telemetry it captured is now derivable post-run from the analyzer's latency histogram (`scripts/analyze-llm-run.ts`, Plan 01) — no in-flight log path needed.

**What stays:** hard-kill via `LLM_BATCH_TIMEOUT_MS` (default bumped per D-05 — see Tuned Defaults table above). Single-tier watchdog.
