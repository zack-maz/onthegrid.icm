## Decisions Made

- **Shape (C) — `allTiersGreen` boolean AND `tierStatus` per-tier rollup, not just the boolean.** Per RESEARCH Open Question 5: ~5 extra lines of YAML for strictly better operator UX. The single-glance boolean gives the gate signal; the per-tier rollup gives the operator a finger-point at the failing tier without opening the full `/api/health` response. The merged API Health tab's audit-result banner picks up both fields automatically (the route is shape-agnostic — `res.json(parsed)` passes through whatever Redis returns).
- **Path (B) for cold-cache self-heal — no `PROD_CRON_SECRET` secret added.** Per RESEARCH Open Question 6: trust the cold-cache self-heal at `llmExtractionPipeline.ts:123-135` (probes `events:llm:v3` BEFORE the cooldown check; empty cache → bypasses cooldown automatically). The daily 4am tick will populate the cache if the gate check finds it cold. Operators who need faster feedback can manually run `/api/cron/refresh-events?force=true` via curl with their own Bearer (Phase 27.4.6 D-11 force-trigger).
- **Fold-in vs split-out for Step 3.** The plan + PATTERNS were explicit that the assertion result populates the new `allTiersGreen` + `tierStatus` payload fields, so splitting them produces a race where the payload is composed before the assertion runs (or vice-versa). Fold-in keeps the assertion + payload + exit-code atomic — Step 3 succeeds iff every tier is green, and the sidecar reflects that single source of truth.
- **Step 6 in-memory cross-check, NOT curl round-trip.** A `curl /api/audit-status` in Step 6 would race the Upstash REST replication window between Step 3's write and Step 6's read. The gate signal lives on Step 3's `process.exit(allTiersGreen ? 0 : 1)` — Step 6 just checks `steps.sidecar.outcome` in-memory, which is GitHub Actions' own event-loop state (no network round-trip).
- **Comment-text rephrase to avoid spurious grep match.** The plan's verification step #6 asserts `grep -c "process.exit(allTiersGreen"` returns exactly 1. My initial Step 6 comment included a code-shaped citation `process.exit(allTiersGreen ? 0 : 1)` for cross-reference, which made grep return 2. Rephrased to english prose ("its inline node script's final exit-code branch") to satisfy the verification check while preserving the cross-reference. The intent of the verification (gate signal lives in exactly one CODE-LEVEL exit branch) is met — the documentation reference is preserved as readable prose.
- **Existing W-3 test BYTE-UNCHANGED.** Per PATTERNS §Shared / `it()` extension over modification: extending the contract by adding NEW `it()` blocks (not modifying the original) preserves the W-3 forward-compat property and pins both directions of the new schema. `toMatchObject` on the original test is permissive on extra fields — it stays green even when the workflow writer adds `allTiersGreen` + `tierStatus`.
