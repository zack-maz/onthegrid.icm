## Decisions Made

- **IIFE vs top-level helper for the Precip row projection.** The plan offered both as acceptable; chose IIFE because (a) the projection is consumed once and would be overhead to extract, (b) the existing Events row uses an inline shape that diverges from the `...spread` pattern without going through a helper, so the IIFE is consistent with the file's existing style, and (c) a helper would need to thread `aggregateHealth + precip` through props, adding indirection without buying expressive power.
- **NON_CACHE_ENDPOINTS allowlist encoded inline in the test, not imported.** The 7 names in the allowlist mirror the file-header comment at `server/lib/healthSources.ts:28-33`. Encoding them inline keeps the test independently auditable — if a future drift expands the allowlist in production code, the test must be updated explicitly, preventing silent drift via re-export.
- **Test 10 asserts the rendered `/api/water/precip` row, not a "Precip" string.** The plan's literal `screen.getByText('Precip')` would have failed because the rows[] array is no longer rendered to DOM (Polling Stores section was removed in commit `cc3b388`, 2026-05-06 — see Deviation #1 below). The test was adapted to assert the rendered API Health table row, which is the operator-visible signal of the change in the merged tab.

**2. [Rule 3 — Blocking] Temporal-dead-zone ReferenceError when the Precip-row IIFE referenced `aggregateHealth` before its declaration**

- **Found during:** Task 3 (initial implementation of the IIFE inside the rows[] array)
- **Issue:** The plan's `<action>` block instructed inserting the IIFE inside the `rows: ApiRow[]` array (line 463) which references `aggregateHealth?.endpoints?.waterPrecip`. However, `aggregateHealth` is destructured from `useHealthStatusContext()` at L589 — _below_ the rows[] declaration. JavaScript's `const` is hoisted but uninitialized in the temporal dead zone, so the IIFE (which executes synchronously during rows[] construction) would throw `ReferenceError: Cannot access 'aggregateHealth' before initialization`. This is a hard runtime error, not a TS-level issue, and would have crashed every render of `DevApiStatus`.
- **Fix:** Moved the entire `useHealthStatusContext` destructure block (`aggregateHealth`, `healthLoading`, `healthError`) and the derived `hasCriticalUnhealthy` constant to the line immediately after the `precip` selector and before the `const rows: ApiRow[] = [` declaration. The move is name-preserving: every downstream consumer (TabButton indicator at L675, DevApiStatusAllApisTab mount at L740-742) keeps its identifier site and binds to the same symbols. The original location at L599 was replaced with a comment block documenting the move and explaining the TDZ rationale.
- **Files modified:** `src/components/ui/DevApiStatus.tsx` (one block moved; ~10 LOC added including the explanatory comment at the original site)
- **Verification:** All 54 DevApiStatus sibling tests pass; `tsc --noEmit` exits 0; the `aggregateHealth?.endpoints?.waterPrecip` reference inside the IIFE resolves without TDZ error during render.
- **Committed in:** `120805a` (Task 3 commit, alongside the IIFE addition)
