## Drift Findings (deferred to W2 / W7 sub-4)

Each drift was identified by reading the writer-side route and the reader-side prober (`server/routes/health.ts` + `server/routes/cron-health.ts` + `server/routes/cron-warm.ts`) and finding cache-key spelling mismatches:

### DRIFT-1: `/api/news` writes `news:feed`; probers read `news:gdelt`

- **Operational impact:** `/health` and daily cron-health source-freshness check report stale-or-empty for news even when `/api/news` is fully fresh. The `news:gdelt` key is the LLM extractor's NEWS-context side-input, NOT the canonical news-route freshness witness.
- **Natural fix locus:** **W2** — when the new `/api/health` endpoint is built with the corrected `SOURCE_KEYS` table per D-25, `news` should map to `news:feed`. The `news:gdelt` side-input deserves its own probe row in the W2 design.

### DRIFT-2: `/api/sites` writes `sites:v3`; probers + cron-warm write+read `sites:v2`

- **History:** Phase 27.3.1 Plan 11 bumped sites cache shape and key (`sites:v2` → `sites:v3`). `/health`, `cron-health`, and `cron-warm` were not updated alongside. Snapshot tier (24h cache, ~720 sites) hides this from end-users.
- **Natural fix locus:** **W2** (prober `SOURCE_KEYS`) + **W7 sub-4** (cron-warm shape correction — write `sites:v3` with the envelope `{sites, filterStats}`).

### DRIFT-3: `/api/water` writes `water:facilities:v3`; probers + cron-warm write+read `water:facilities`

- **History:** Phase 27.3.1 + 27.3.2 bumped water cache key through v2 → v3. `/health`, `cron-health`, and `cron-warm` were never updated.
- **Operational impact:** Identical shape to DRIFT-2.
- **Natural fix locus:** Same as DRIFT-2 — **W2 + W7 sub-4**.

### DRIFT-4: `/api/markets` cache key has range suffix; static SOURCE_KEYS only probes `:1d`

- **Severity:** Low — the default range IS the polled range per CLAUDE.md.
- **Natural fix locus:** **W2 PLAN** documents the choice (probe just the default `:1d`).
