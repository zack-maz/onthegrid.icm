**Gathered:** 2026-05-17

<domain>
## Phase Boundary

Decide and document the real shape of the LLM cascade. Either re-enable the OpenRouter fallback that has been silently disabled since Phase 27.4.4 (`skipOpenRouter: true` hardcoded at `server/lib/llmEventExtractor.v3.ts:622, 929`), or amend the docs that currently advertise a NIM → OpenRouter cascade that does not exist in code. Drive that choice from one fresh measurement of OpenRouter free-tier rate-limit behavior — not from the stale Phase-27.4.4 16/16 observation that pre-dates the Phase-29 cascade narrowing.

**Trigger:** 2026-05-17 04:00 UTC daily cron showed NIM 39 rate_limit errors → circuit breaker tripped → 50+ batches `reason: "skipped:breaker"` → 0 OpenRouter attempts (`used: 0 / cap: 200`). Phase 30 closed clean because operator-attended Run 1 + Run 2 happened during low-traffic windows; this is the bad-path failure mode they missed.

**Requirements covered (new in 30.1):** none formally — this is gap-closure work surfaced by operator review at the Phase 30 boundary. The phase makes Phase 29 D-01's "NIM (primary) + OpenRouter (fallback)" stance either true (cascade restored) or honestly amended (NIM-only declared).

## Implementation Decisions

### Phase Scope

- **D-01: Right tier scope, with same-phase pivot to Minimum on bad probe result.** Re-test OpenRouter free-tier rate-limit behavior first; the probe result selects the rest of the phase:
  - **< 50 % rate_limit fail (viable):** Remove `skipOpenRouter: true` from `server/lib/llmEventExtractor.v3.ts:622` (main batch path) and `:929` (split-half retry path). Rewrite `server/__tests__/lib/freeClaudeRouter.test.ts:262-283` P3 test to assert the inverse — `skipOpenRouter` defaulted-false produces OR rows in routingTrace when NIM 429s. Add a positive-case test that `skipOpenRouter: false` (or absent) lets OR fire on NIM rate_limit / breaker fall-through. Redeploy. Force-trigger one cron via `GET /api/cron/refresh-events?force=true` (Bearer). Confirm `events:llm-summary:v3.routingTrace` contains at least one `provider: 'openrouter'` row.
  - **50 - 90 % rate_limit fail (case-by-case):** Per seed's open-question #4: paid-OR conversation. Phase 30.1 ships Minimum-scope docs with the measured numbers and explicitly defers paid-OR / rate-limit tightening to Phase 31 follow-up. No code change in 30.1.
  - **> 90 % rate_limit fail (not viable):** Drop to Minimum scope in same phase. No `skipOpenRouter` flip. Amend `docs/architecture/llm-pipeline-reliability.md` + ADR-0010 sub-block to declare "NIM-only active; OpenRouter dormant pending Phase-31-or-later re-validation." Keeps Phase 30.1 atomic on the cascade question regardless of outcome.

- **D-02: Pre-flight branch discipline.** Planner / executor MUST cut `feature/30.1-cascade-fallback-fix` from `main` after PR #20 (Phase 30) merges, before any code change. CONTEXT.md, DISCUSSION-LOG.md, and the checkpoint file may sit on the current Phase-30 branch as scaffold work; nothing else does.

### OpenRouter Re-Validation Probe

- **D-03: Standalone script** at `scripts/probe-openrouter.ts`. Runs via `node --env-file=.env.local --import tsx/esm scripts/probe-openrouter.ts`. Mirrors `scripts/eval-replay.ts` and `scripts/refresh-water-facilities.ts` shape. Uses the production `OPENROUTER_API_KEY` env var — rate limits are per-account, so the dev-run measurement is representative of prod behavior. Zero new prod surface (no temp endpoint).

- **D-04: Sample shape.** N = 30 single-event payloads, 100 ms gap between calls. Single-event payload matches v3's effective batch shape after Phase 30 tuning. N = 30 is sufficient for binomial confidence at ≈ ±10 % across the three viability buckets. ~5 minute wall-clock total.

- **D-05: Viability thresholds (seed's original three-bucket scheme).**
  - `< 50 %` fail → OR viable → flip `skipOpenRouter` to false in both call sites + rewrite test (D-01 happy path).
  - `50 – 90 %` fail → case-by-case → 30.1 ships Minimum-scope docs with measured numbers + Phase 31 follow-up note (paid-OR conversation deferred).
  - `> 90 %` fail → not viable → 30.1 ships Minimum-scope docs only.

- **D-06: Probe output committed at `.planning/phases/30.1-.../30.1-or-pulse-snapshot.json`** + 1-paragraph results summary in PLAN.md. Mirrors Phase 30 D-08 `run-1-throttle-snapshot.json` pattern. Schema captures: `timestamp`, `n`, `gapMs`, `model`, `results[]` (each `{attempt, status, latencyMs, retryAfterMs?}`), summary `{rateLimitedCount, rateLimitedPct, decision}`. Auditable forever, re-runnable for regression checks.

### Breaker-Trip Behavior Contract

- **D-07: If OR is viable, the cascade as-built is the full fix.** `server/lib/freeClaudeRouter.ts:341-363` already implements `includeOpenRouter = !opts.skipOpenRouter`, fall-through reason taxonomy (`fall_through:nvidia_nim_*`), and per-event retry budget. Removing the two `skipOpenRouter: true` lines + rewriting the P3 test gives "NIM primary, OR on rate_limit/breaker fall-through" with no new routing code. The Phase 30 D-02 retry/backoff envelope governs OR identically.

- **D-08: If OR is NOT viable, the documented breaker-trip behavior is "drop batch + Pitfall-1 GDELT terminal fallback" — current runtime behavior, declared honestly in docs.** `server/routes/events.ts` Pitfall 1 bridge already serves raw GDELT when `events:llm:v3` is empty. ADR-0010 already declares raw GDELT as terminal fallback. Phase 30.1 adds one paragraph to `docs/architecture/llm-pipeline-reliability.md`:

  > "When the NIM circuit breaker opens mid-run, batches drop and `/api/events` serves raw GDELT via the Pitfall 1 bridge. The map never goes blank, but enrichment quality degrades to the raw GDELT ontology. Operator visibility of this transition is currently limited to `/api/operator-status` Bearer-gated surfaces; a richer dashboard signal is deferred."
  > Zero runtime code change in this branch.

- **D-09: `server/lib/llmCircuitBreaker.ts` is NOT touched in 30.1.** Current breaker (>30 % error in 10-call window, 5-min pause) is Phase 27.4.2 / 27.4.3 tuning. Phase 30 deliberately left it out of scope; 30.1 follows the same discipline. If Phase 31's 7-day watch shows breaker drift after the cascade restore, breaker re-tuning gets its own ADR-0010 sub-block.

- **D-10: Audit-trail honesty in the commit + ADR-0010 sub-block.** The commit that flips `skipOpenRouter` (or the doc-only commit that declares NIM-only, in the bad branch) names the percentages and date explicitly. Required wording template:
  > "Re-tested OR free-tier YYYY-MM-DD via scripts/probe-openrouter.ts: N/30 rate_limited (NN%). Conclusion: <restored cascade | Minimum scope>. Phase 27.4.4's 16/16 measurement <stale by N months | still holds>."
  > Same line lands in the ADR-0010 sub-block under a new `## Phase 30.1 Sub-block (appended YYYY-MM-DD)` heading, mirroring the Phase 30 sub-block convention. The artifact prevents the next operator from making the same call.

### Testing & Validation

- **D-14: Force-trigger + analyzer is the live-path validation protocol.** After the `skipOpenRouter` flip (or the doc-only commit), `GET /api/cron/refresh-events?force=true` with Bearer. Then `scripts/analyze-llm-run.ts` (Phase 30 D-01) against `events:llm-summary:v3`. routingTrace must contain at least one `provider: 'openrouter'` row in the cascade-restored branch; routingTrace must contain only `provider: 'nvidia_nim'` rows in the NIM-only branch. ### Commit Discipline
