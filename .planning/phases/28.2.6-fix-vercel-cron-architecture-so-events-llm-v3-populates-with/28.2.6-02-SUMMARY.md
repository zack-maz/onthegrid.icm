- `@vercel/functions ^3.5.0` installed as runtime dependency, alphabetically positioned between `@vercel/analytics` and `@vercel/speed-insights` in `package.json`'s `dependencies` block (NOT devDependencies — invoked at request time).
- `server/lib/safeWaitUntil.ts` is the SOLE import path of `@vercel/functions` `waitUntil` in this repo. The shim:
  - Probes `globalThis[Symbol.for('@vercel/request-context')]` (the same probe `@vercel/functions`' own `getContext()` uses internally — verified at `packages/functions/src/get-context.ts`).
  - On Vercel: delegates to `waitUntil(promise)` inside try/catch so internal package errors (TypeError on non-Promise input, etc.) cannot propagate to the cron route handler.
  - Off Vercel: falls back to `promise.catch((err) => log.warn({ err }, '...'))` so Express dev + Vitest run the work AND late rejections never escape as unhandled rejections.
  - Returns `void` (NOT `Promise<void>`) — TypeScript-strict-mode enforcement of D-12 (caller cannot accidentally `await` it).
- `server/lib/llmExtractionPipeline.ts` IIFE call site changed from `void (async () => {...})()` to `safeWaitUntil((async () => {...})())`. Single transformation; the IIFE body (Plan 01's periodic-flush wiring + final flush + outer try/catch) is byte-unchanged.
- `vercel.json` extended with `functions['api/vercel-entry.js'].maxDuration: 300` — documentation-only (Hobby Fluid Compute default IS already 300s) but defensive against Vercel default change.

## Decisions Made

- **Sole-call-site discipline (D-08 / D-09).** `safeWaitUntil` is the only place in the repo that imports `waitUntil` from `@vercel/functions`. Future callers MUST import the shim, never the package directly. Rationale: gives a single integration point for both Vercel and local runtimes; future package drift only breaks one file.
- **Vercel detection signal: `Symbol.for('@vercel/request-context')` NOT `process.env.VERCEL` (Pitfall 5).** The Symbol-keyed global is the runtime context signal; the env var is build-time. Verified by inspecting `@vercel/functions`' own `getContext()` source.
- **Function returns `void`, not `Promise<void>` (D-12).** TypeScript-strict-mode prevents `await safeWaitUntil(...)` at compile time (the type is `void`; you cannot `await` it). This is the type-system enforcement of D-12 — the verified-broken commit `b016a5c` `await`ed the IIFE and was reverted in `b4bf4a3`.
- **Try/catch around the Vercel-path `waitUntil` call.** `@vercel/functions waitUntil` throws TypeError on non-Promise input (verified at `packages/functions/src/wait-until.ts:5-7`). The catch ensures the cron route handler never crashes on internal package errors; falls through to the local-dev catch path.
- **`vercel.json maxDuration: 300` is documentation-only.** Hobby Fluid Compute default IS already 300s. Declaring it explicitly is defensive against Vercel changing the default in the future without our knowing.
- **Cross-plan defense — keep both mocks (Task 3 Step 5).** Plan 01's three Wave 0 test files retain the original `vi.mock('@vercel/functions', ...)` declaration AS WELL AS the new `vi.mock('../../lib/safeWaitUntil.js', ...)` declaration. The former is now inert under Plan 02 (the SUT no longer imports `@vercel/functions` directly) but stays as defense-in-depth: if a future regression removes the safeWaitUntil mock, the @vercel/functions mock still keeps the IIFE running under test.
