  calls in `resolveViaPoiAmenity`, `resolveViaNominatimDirect`, and

### WR-02: DLQ eviction JSON re-stringify may not match the stored sadd payload — srem silently no-ops

**Files modified:** `server/lib/llmDLQ.ts`
**Commit:** `c2f730a`
**Applied fix:**

- Replaced the `parsed.map((e) => JSON.stringify(e))` re-serialization with a
  paired-structure approach: map each raw `smembers` member to
  `{ raw, parsed }`, filter out un-parseable entries, sort by
  `parsed.timestamp`, then slice and project back to the ORIGINAL raw string
  for `srem`. This guarantees byte-exact match with the sadd payload
  regardless of Upstash REST round-trip behavior (key ordering, whitespace,
  number precision).
- Defensive: if `smembers` returns an object instead of a string for some
  transport path, the raw pair falls back to `JSON.stringify(raw)` so we
  never pass a non-string to `srem`.

**Verification:**

- `npx tsc --noEmit -p tsconfig.json` — passes.
- `npx vitest run server/__tests__/lib/llmDLQ.test.ts` — 54/54 pass
  (includes DLQ3: 205 entries → srem reduces back to 200 with the correct
  6 oldest-by-timestamp).

**Commit:** `9bb15aa`
**Applied fix:**

  - Split the prior `if (candidates.length < 2)` branch into two cases:
