# Phase 27.4 Plan 09: DevApiStatus Events Tab Summary

Dev-only observability surface for the v2 LLM pipeline — every 27.4 decision visible in a single pane of glass so ops can verify the D-25 accuracy gate before flipping LLM_PIPELINE_V2 to true in prod.

## What Shipped

1. **Extended /api/events/llm-status payload (server)**
   - Returns the full v2 observability block in dev: `schemaVersion`, `callHistory`, `tokenCounters`, `dlqCount`, `dlqRecent` (last 50), `breakerState`, `evalScore`, `provenanceCounts`, `suspectCount`, `recentEvents` (last 50 from `events:llm:v2`), and `paused` (B5 soft-cap surface).
   - Still returns 404 in production (threat T-27.4-09-01 mitigation preserved).
   - Each optional source (`listDLQ`, `loadRecentEnrichedEvents`, `shouldPauseNewEvents`) is individually try/caught — a Redis outage returns `[]`/`false` rather than 500ing the endpoint.
   - `loadRecentEnrichedEvents` projects the cached v2 entities into `RecentEnrichedEvent` shape. Falls back gracefully for fields not persisted on the entity (location hierarchy defaults the city slot to `data.locationName`, provenance defaults to `gdelt-actiongeo-fallback`).
   - W4 fix: no raw `process.env.LLM_PIPELINE_V2` reads remain in `server/routes/events.ts` — both callsites now go through `isPipelineV2()` for request-time flag flips.

2. **Client type mirror (src/types/llm.ts)**
   - New file. `GeocodeProvenance` string-literal union — client-side copy of `server/lib/llmSchema.GEOCODE_PROVENANCE_VALUES` so `src/hooks/useLLMStatusPolling.ts` can type `recentEvents[].provenance` without reaching into the server/ tree.

3. **Extended LLMStatus interface (src/hooks/useLLMStatusPolling.ts)**
   - Added 9 optional fields (`schemaVersion`, `callHistory`, `tokenCounters`, `dlqCount`, `dlqRecent`, `breakerState`, `evalScore`, `provenanceCounts`, `suspectCount`, `recentEvents`, `paused`) mirroring the server payload.
   - Added `RecentEnrichedEvent` exported type.
   - Extended `LLMRunSummary` with the same v2 fields so cold-start Redis reads still surface the observability data.

4. **DevApiStatusTab union extension (src/types/ui.ts)**
   - `'events'` added to the union. `src/stores/uiStore.ts` picks up the change automatically through the typed setter — no runtime change needed.

5. **DevApiStatus.tsx Events tab + 8-block EventsFiltersSection**
   - Tab is dual-gated: `llmStatus?.schemaVersion === 'v2' && import.meta.env.DEV`. Prod bundles tree-shake the entire block.
   - Auto-snap-back effect restores Overview when the gate closes mid-session.
   - 8 block sub-components in RESEARCH-mandated order:
     1. `WaterfallBlock` (D-16) — Grouping → LLM → Geocoding → Done, each with ProgressBar.
     2. `HistogramsBlock` (D-17) — color-coded provenance distribution + LLM call success rate.
     3. `DrillDownBlock` + `DrillDownRow` (D-18, B4) — collapsible last 50 enriched events. Each row summary shows city/admin1/country · precision · confidence · weapon/target. Expanded reveals full hierarchy, reasoning (italic), per-event tokens, color-coded provenance, and clickable source links. "Copy prompt+response JSON" button POSTs to `/api/events/llm-replay/:groupKey` (Plan 08 D-21 endpoint) and writes the returned JSON to the clipboard with 2s "Copied!" feedback.
     4. `CallLogBlock` (D-19) — last N calls with provider, tokens, duration, batch size, and relative timestamp. Green/red ok dot.
     5. `BudgetBarsBlock` (D-36) — per-provider (Cerebras 1M / Groq 200k) ProgressBars with ⏸ glyph when breaker is paused.
     6. `EvalScoreBlock` (D-20) — 5km / 20km / 100km accuracy counters with PASS/FAIL badge next to the 20km figure (D-25 gate @ ≥80%).
     7. `DlqBlock` (D-30) — "DLQ: 0 entries" zero-state, else list reason + truncated group id + relative timestamp.
     8. `SuspectBlock` (D-23) — amber count when non-zero.
   - `PROVENANCE_COLORS` map: green own-site, blue poi-amenity, cyan direct-nominatim, purple verified-2pass, amber gdelt-actiongeo, orange bellingcat.
   - "Paused — soft cap" amber pill in the section header when `llmStatus.paused === true` (B5 surface).

## Deviations from Plan

### Auto-fixed Issues

1. **[Rule 3 — Missing test mocks] Added mocks for `llmDLQ` + `llmTokenBudget` to server events.test.ts**
   - **Found during:** Task 1 test run
   - **Issue:** The new /llm-status handler imports `listDLQ` from `llmDLQ.js` and `shouldPauseNewEvents` / `prioritizeBySeverity` from `llmTokenBudget.js`. The events.test.ts file lacked `vi.mock` for those modules, which would have caused the server route to try to reach real Redis during tests.
   - **Fix:** Added `vi.mock('../../lib/llmDLQ.js', …)` and `vi.mock('../../lib/llmTokenBudget.js', …)` with controllable mock functions for `mockListDLQ`, `mockShouldPauseNewEvents`, `mockPrioritizeBySeverity`. Reset them in the route-test `beforeEach`.
   - **Files modified:** server/**tests**/routes/events.test.ts
   - **Commit:** 529825e

### Decisions Made During Execution

1. **Graceful RecentEnrichedEvent projection (Task 1)**
   - The plan's pseudocode dereferenced `d.location.country`, `d.confidence`, `d.weaponType`, etc., from the cached v2 entity's `data` field. But `enrichedV2ToEntities` currently persists only `locationName`, `summary`, `precision`, `actors`, `sourceCount`, `sourceTier`, `casualties`, `llmProcessed` — NOT the full hierarchy / weapon / target / confidence / reasoning / geocodeProvenance.
   - Decision: Keep the contract wide (all fields present on the client interface) but degrade gracefully on the server — default the missing fields to `null` or sensible placeholders (city ← locationName, provenance ← `gdelt-actiongeo-fallback`). A follow-up plan can enrich `enrichedV2ToEntities` without any client interface change.
   - This avoids expanding Plan 09's scope into the entity-adapter surface (which is Plan 06 territory).

2. **Tab auto-snap-back parity**
   - Extended the existing `activeTab === 'water' && !showWaterTab` effect to include an `events` case. Prevents rendering an empty tab body when an operator flips the pipeline back to v1 or switches out of DEV mid-session.
