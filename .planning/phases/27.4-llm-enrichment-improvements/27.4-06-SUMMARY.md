# Phase 27.4 Plan 06: v2 Extractor + Flag-Routed Barrel Summary

**v2 extractor ships with BATCH_SIZE=2, 3 conditional prompt blocks (NEWS + BELLINGCAT + TEMPORAL) read from existing Redis caches, structured hierarchy output, and resolver integration (D-22 provenance). Barrel now routes v1/v2 via `isPipelineV2()` at call-time returning a tagged union — consumers branch on `schemaVersion`. Events.ts picks up B5 soft-cap gate + prioritizeBySeverity and produces `enrichedV2ToEntities` with provenanceCounts + suspectCount telemetry for Plan 09.**

## What Shipped

### Task 1 — `server/lib/llmEventExtractor.v2.ts` + tests (commits `f0bbe1f` RED, `ce0ba25` GREEN)

**TDD cycle:** wrote 13 failing tests first (plan specified 13 behaviors; 1:1 mapping), confirmed RED via `Cannot find module llmEventExtractor.v2.js`, implemented the module, all 13 tests pass.

**Named exports:**
- `processEventGroupsV2(groups, onBatchComplete?) → V2ExtractionRun` — sole batch-processing entry point. Returns `{ events, matchedNewsByGroup, bellingcatByGroup }` so the geocoder can thread per-group context without re-reading Redis.
- `geocodeEnrichedEventsV2(events, groupsByKey, matchedNewsByGroup, bellingcatByGroup, onComplete?) → GeocodedEnrichedEventV2[]` — calls `resolveLocation` once per event; populates ctx.articleTitles from headlines (W3) and ctx.bellingcatCoord from per-group map (W2); derives precision + suspect via llmSchema helpers.
- `buildBatchUserPromptV2(contexts) → string` — composes the final user prompt: GDELT headers + 3 conditional blocks.
- `BATCH_SIZE = 2` (D-10) exported for test assertion.
- `SYSTEM_PROMPT_V2` exported for eval harness / prompt replay.
- Types: `V2ExtractionRun`, `GeocodedEnrichedEventV2`, `NewsArticleForPrompt`, `PromptContext`, `PriorEnrichedEventForPrompt`.

**Prompt blocks (all conditional — emitted only when data present):**
1. **NEWS BLOCK (D-06)** — `--- NEWS BLOCK (tier-tagged) ---` with `[T1/T2/T3] <title>` lines. Matched by ±24h publishedAt window per RESEARCH.md Open Q A4 (time-only, NOT haversine — news cache has no per-article lat/lng).
2. **BELLINGCAT BLOCK (D-07)** — `--- BELLINGCAT OSINT (high-trust) ---` with `<title> [Bellingcat coord hint: lat, lng]`. Coords parsed from matched article titles via `extractBellingcatGeo`.
3. **TEMPORAL BLOCK (D-08)** — `--- TEMPORAL CONTEXT (N recent events in region) ---` with up to 3 prior events (A5). ±1° bbox, ±72h window. Sourced from `events:llm:v2` cache — this plan's dogfood loop.

**System prompt invariants (tested):**
- Explicitly forbids lat/lng emission (D-05).
- Requests every hierarchy field (country, admin1, city, neighborhood, landmark, confidence) and explicitly states they're nullable.
- Explicitly forbids `precision` field — server derives via `derivePrecision(hierarchy)`.

**Reviewer-flagged fixes baked in at first-ship (all tested):**
- **W1 — DLQ on Zod fail:** `batchResponseV2.safeParse` failure causes one `enqueueDLQ({ id: group.key, reason: 'zod_fail', lastError, timestamp })` per group in the failed batch. No throws — graceful degradation preserved (D-29).
- **W2 — Bellingcat coord passthrough:** per-group `bellingcatByGroup` map populated from parsed titles, threaded to `geocodeEnrichedEventsV2` and into `ResolveContext.bellingcatCoord`. Resolver's branch 5 now reachable in production.
- **W3 — Article headlines vs URLs:** `ctx.articleTitles` sourced from `matchedNews.map(a => a.title)`, NOT URLs. Test 12 asserts this explicitly.

  groups: EventGroup[],

- Routes via `isPipelineV2()` read at call time (W4 — no raw `process.env.LLM_PIPELINE_V2` access).

None. The plan's `<threat_model>` (T-27.4-06-01 through T-27.4-06-05) is fully mitigated by:
