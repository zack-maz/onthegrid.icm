## Decisions Made

- **Kept `forwardGeocode` verbatim** — preserves v1 callers + Plan 03 skeleton resolver; `forwardGeocodeConstrained` is the superset Plan 05 will adopt. Deleting the old would force cross-plan coupling before Plan 05 lands.
- **Hard-coded ME defaults sourced from `server/lib/meBounds.ts`** — threat T-27.4-04-01 mitigation. The `readonly [number, number, number, number]` type on `ME_VIEWBOX` + default-fallback via `opts.viewbox ?? ME_VIEWBOX` prevents both accidental mutation and resolver-bypass by user-supplied input.
- **`URLSearchParams.set('countrycodes', opts.countrycodes ?? ME_COUNTRY_CODES)`** instead of inline ternary — matches the plan's Step 3 action block exactly and keeps the default-fallback readable.
- **amenity/q mutual exclusion** implemented via if/else in function body (`if (opts.amenity) params.set('amenity', opts.amenity); else params.set('q', placeName);`) rather than trying to handle both — matches Nominatim API contract and is easy to unit-test (Test 3 in behavior block).
- **Graceful degradation → `[]`** (not `null` or throw) on every error branch — consistent with the "adapter never throws" discipline and lets the resolver layer treat path exhaustion via array-length check rather than null-guard everywhere.
- **Test-import pattern: dynamic `await import(...)` inside each `it` block** — mirrors the existing file's forwardGeocode tests so the mock-fetch state is fresh per test. The plan's `vi.stubGlobal('fetch', mock)` pattern was substituted with the existing file's `globalThis.fetch = mock as unknown as typeof fetch` pattern for byte-identical mock discipline across the whole file.
