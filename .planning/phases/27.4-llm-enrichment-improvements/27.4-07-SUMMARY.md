# Phase 27.4 Plan 07: Reliability + Rate-Limiting + Observability Primitives Summary

Ship four tightly-scoped modules — circuit breaker, bounded DLQ, daily token budget, and an integrated `callLLM` retry loop — that every LLM call (reranker Plan 05, extractor Plan 06, future uses) now flows through with graceful degradation preserved.

## What Shipped

### Task 1 — Three new primitive modules

**`server/lib/llmCircuitBreaker.ts`** (D-31)
- Sliding window on last 10 calls per provider; trips to `paused` for 5 minutes when error rate > 30%
- Module-level singleton state survives warm starts on Vercel Fluid Compute; cold-start worst-case is 10 calls to rebuild the window (inside D-28 retry budget)
- On trip, outcomes buffer is cleared to prevent immediate re-trip on the next error (Pattern 8 requirement)
- Exports: `record`, `isAvailable`, `getBreakerState`, `__resetBreakerForTests`, `PAUSE_DURATION_MS`
- 8 behavior tests (CB1–CB8)

**`server/lib/llmDLQ.ts`** (D-30)
- Redis-backed bounded DLQ at key `events:llm-dlq`, max 200 entries, 7-day TTL
- Oldest-by-timestamp eviction when SCARD > 200
- `lastError` capped at 500 chars (Pitfall 7 — prevents Zod-issue payload explosion)
- All three functions (`enqueueDLQ`, `listDLQ`, `countDLQ`) swallow Redis errors — never throw (D-29 graceful degradation contract)
- Payload parser tolerates both string and already-parsed-object responses from Upstash
- 6 behavior tests (DLQ1–DLQ6)

**`server/lib/llmTokenBudget.ts`** (D-32..D-35)
- Redis key `llm:tokens:{provider}:YYYY-MM-DD` (UTC date), 48h TTL via `redis.multi().incrby().expire().exec()` pipeline (A3 atomicity)
- `DAILY_LIMITS`: Cerebras 1,000,000 TPD / Groq 200,000 TPD (free tier)
- `budgetState(provider, used)` returns `'ok' | 'soft' | 'hard'` using 0.8 / 0.95 thresholds
- 9 behavior tests (TB1–TB9) + DAILY_LIMITS smoke test (TB10)

### Task 2 — `callLLM` extension

Rewrote the body of `server/adapters/llm-provider.ts callLLM` to wire the three primitives together:

- Every provider attempt gated on `isAvailable(provider) && budgetState(provider, used) !== 'hard'`
- Retry budget = 2 attempts per provider with 1s / 4s exponential backoff + ±250ms jitter (A5)
- On success: `incrDailyTokens(provider, tokens)` + `record(provider, 'ok')` + `appendCallHistory` (shift-append, capped at 20 entries) + mirror `tokenCounters` + `breakerState` onto `llmProgress`
- On throw: `record(provider, 'err')` + `appendCallHistory` with `ok: false` (Repudiation T-27.4-07-04 mitigation)
- On null content without throw: fall straight to next provider (schema fail doesn't retry same prompt)
- Graceful degradation: returns `null` only when every attempt fails → upstream falls back to raw GDELT (D-29)
- `json_schema.name` bumped to `event_extraction_v2` when `isPipelineV2()` returns true (Pattern 1), read via centralized `isPipelineV2` helper rather than raw `process.env` (W4 fix — operators can flip without rebuild)
- Optional `opts.batchSize` parameter (default 1) threads through to `appendCallHistory` for per-batch tagging
- `CEREBRAS_MODEL` + `GROQ_MODEL` promoted to exported constants
- 7 new integration tests (A–G) covering breaker-skip, budget-skip, token increment, retry-then-fallback, total-failure null, call-history population, post-exhaustion breaker-state update

### Task 3 — Soft-cap helpers

Extended `server/lib/llmTokenBudget.ts` with two helpers for Plan 06's `events.ts` fire-and-forget block:

- **`shouldPauseNewEvents(): Promise<boolean>`** — returns `true` when either provider is in `soft` state (>= 80% budget); events.ts reads this once per cycle and serves cached LLM entities when paused (D-33). Returns `false` when both providers are hard-capped because that path is already handled by `callLLM` returning null (D-34).
- **`prioritizeBySeverity(groups): Promise<EventGroup[]>`** — returns the input array unchanged (reference equality) when not paused; when paused, returns a new array sorted by `computeSeverityScore` descending with timestamp desc as tie-breaker (D-35 / B5 fix).
- **`computeSeverityScore(group: EventGroup): number`** — server-local scorer (TYPE_WEIGHTS mirrors `src/lib/severity.ts` without cross-boundary import); per-entity max across the group (not mean) so one high-severity entity is not masked by low-severity noise.
- 7 new tests (TB10–TB16) covering the soft-gate on/off, both-hard edge case, reference-equality no-op, severity ordering, and timestamp tie-breaking.

## Deviations from Plan

### Auto-fixed / Adapted

**1. [Rule 3 - Blocker] `computeSeverityScore` does not exist on the server**

- **Found during:** Task 3 read_first
- **Issue:** Plan referenced `import { computeSeverityScore } from './eventScoring.js'` but `server/lib/eventScoring.ts` exports `computeEventConfidence`, not `computeSeverityScore`. The real function lives in `src/lib/severity.ts` (client side) and server code shouldn't cross the `src/` boundary.
- **Fix:** Created a server-local `computeSeverityScore(group: EventGroup): number` inside `server/lib/llmTokenBudget.ts` using the same formula pattern as `src/lib/severity.ts` — TYPE_WEIGHTS duplicated as static config (~10 lines), per-entity score with recency decay, max across entities for the group score. The plan's "adapt if the real fn takes a notification-shaped input instead" note explicitly allowed this adaptation.
- **Files modified:** `server/lib/llmTokenBudget.ts`
- **Commit:** 813a1bc

**2. [Rule 3 - Blocker] Existing llm-provider tests timing out after the retry extension**

- **Found during:** Task 2 verify
- **Issue:** The four pre-existing `llm-provider.test.ts` cases did not mock the new subsystems (breaker / budget / progress) and used real timers. With the 1s backoff per retry, tests hung until the 10s vitest default timeout. Also, a single Cerebras-fail test that previously supplied 2 `createMock` calls (one per provider) now has 4 attempts (2 per provider) due to the retry budget.
- **Fix:** Rewrote the test file to (a) mock `llmCircuitBreaker`, `llmTokenBudget`, and `llmProgress` modules so per-test state is controllable, (b) use `vi.useFakeTimers({ shouldAdvanceTime: true })` and `vi.advanceTimersByTimeAsync` to skip real backoff sleeps, (c) supply 4 `createMock.mockRejectedValueOnce` responses for the full-failure test so the exhaustion path runs deterministically.
- **Files modified:** `server/__tests__/adapters/llm-provider.test.ts`
- **Commit:** 6f912ce

**3. [Informational] Test file `llmTokenBudget.test.ts` factory hoisting**

- **Found during:** Task 1 initial test run
- **Issue:** Top-level `const multi = () => ...` outside the `vi.mock` factory caused Vitest's hoist error ("Cannot access 'multi' before initialization").
- **Fix:** Inlined the `multi()` builder inside the `vi.mock('../../cache/redis.js', ...)` factory and exposed the jest-mock handles via a sentinel `__mocks` property on the mock module for test-scoped access.
- **Commit:** e9a6350 (no separate commit — caught and fixed during RED/GREEN cycle)
