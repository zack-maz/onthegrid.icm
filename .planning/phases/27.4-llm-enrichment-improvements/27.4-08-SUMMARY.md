### Task 2 — `server/lib/llmEvalHarness.ts` (new, 263 lines)

**Exports:**

- `GroundTruthEvent` — per-event shape carrying `truth.{lat,lng,precision,landmark,country,admin1}` + the `LocationHierarchyV2` the resolver receives.
- `EvalScore` — `{ within5km, within20km, within100km, total }`.
- `loadGroundTruth()` — reads the committed JSON, validates top-level shape, caches in-module. Matches the `sitesSnapshot.ts` pattern: `cachedGroundTruth` starts `undefined`, becomes `null` on failure, stays `GroundTruthFile` on success. `null`/malformed/wrong-shape all log at warn and return null (non-fatal — eval simply reports 0/0 when ground-truth is missing).
- `runEval()` — iterates each ground-truth event through `resolveLocation(ev.hierarchy, { centroidLat: ev.truth.lat, centroidLng: ev.truth.lng })`, computes haversine distance, increments cumulative within5km/within20km/within100km buckets. Writes the result to `llmProgress.evalScore` via `updateProgress` and persists a baseline to Redis under `events:llm-eval-baseline:v2` (90-day TTL). Per-event failures caught and logged; `total` always stays equal to the ground-truth set size so the D-25 deploy-gate ratio `within20km / total >= 0.8` is mathematically sound.
- `__resetGroundTruthCacheForTests()` — test-only hook.

**Key design decision:** resolver-only. Per RESEARCH.md Open Q A6 and Pitfall 8, the harness does NOT call the v2 extractor or `callLLM` directly. Ground-truth hierarchies are pre-curated (effectively "what a perfect extractor would produce"), so the harness exclusively tests the highest-variance code path: the 6-branch resolver. An optional `EVAL_HARNESS_EXTRACT=true` env flag is mentioned in the file header for future expansion but intentionally not wired this plan — the plan explicitly scopes it as deferred.

### Task 3 — Wire runEval + add POST /llm-replay (server/routes/events.ts)

**runEval integration** (inside v2 fire-and-forget block):

```typescript
// ...after geocodeEnrichedEvents returns and BEFORE cache-set/buildSummary
try {
  const evalScore = await runEval();
  log.info({ evalScore }, 'eval harness completed');
} catch (evalErr) {
  log.warn({ err: evalErr }, 'eval harness threw; continuing pipeline');
}
```

Runs only in the v2 branch (v1 is the rollback path; wiring eval to v1 would waste a cycle on code being deleted in 27.5). Called AFTER `geocodeEnrichedEvents` returns so `buildSummary()` downstream picks up `llmProgress.evalScore`. Try/catch ensures a resolver-harness failure can never fail the real pipeline. Per A6 / Pitfall 8 — resolver-only, no token budget impact.

**POST /api/events/llm-replay/:groupKey** (D-21):

Dual-gate per T-27.4-08-01 / Pitfall 6:

1. Route registered ONLY when `NODE_ENV !== 'production'` — the endpoint isn't mounted in prod.
2. In-handler 404 check on `NODE_ENV === 'production'` — defense-in-depth in case env changes post-registration (matches the existing `/llm-status` pattern).

Handler flow:

1. Validate `groupKey`: `typeof string && length <= 200` (T-27.4-08-02 — belt-and-braces).
2. Lookup existing cached v2 entity via `cacheGetSafe<ConflictEventEntity[]>('events:llm:v2')`; `existing = cached.data.find(e => e.id.includes(groupKey))`.
3. Reconstruct the source `EventGroup` from raw GDELT cache via `groupGdeltRows(rawCache.data).find(g => g.key === groupKey)`.
4. Re-extract with current prompt: `processEventGroupsV2([group])`.
5. Return `{ old, new }` — never write back to cache (T-27.4-08-05, Pitfall 6 invariant).

## Key Decisions (in-line reference)

1. **Resolver-only eval** (RESEARCH.md A6 / Pitfall 8). runEval goes through `resolveLocation(hierarchy, ctx)` only — never the extractor or `callLLM`. Zero daily token impact. An `EVAL_HARNESS_EXTRACT=true` flag is mentioned in the file header but explicitly deferred.
2. **v2-only harness wiring.** runEval is called only in the v2 branch. v1 is rollback-only and will be deleted in 27.5.
3. **Placement inside fire-and-forget block:** AFTER geocodeEnrichedEvents (so it doesn't waste cycles when the geocoder fails), BEFORE the eventual `buildSummary()` call in the enclosing fire-and-forget cleanup (so the same run's summary picks up evalScore without a second pass).
4. **Per-event try/catch** — harness individual event failures are non-fatal and keep `total` honest.
5. **Baseline persistence** — Redis `events:llm-eval-baseline:v2` with 90-day TTL. Write failure is logged, non-fatal.
6. **/llm-replay dual-gate** — route registration guard + in-handler 404 (Pitfall 6 defense-in-depth).
7. **groupKey sanitization** — typeof + length cap 200 (T-27.4-08-02); no regex allowlist because Express already blocks path-traversal chars and the key is used purely as a Map lookup.
8. **READ-ONLY cache invariant** — replay handler must not `cacheSetSafe('events:llm:v2', ...)`. Asserted in test via cacheSet mock call inspection.
