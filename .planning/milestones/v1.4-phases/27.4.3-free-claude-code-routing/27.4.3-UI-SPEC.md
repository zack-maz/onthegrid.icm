## Spacing Scale

Reuse the project's existing Tailwind 4-multiple scale. The canonical set is `4, 8, 16, 24, 32, 48, 64`. Two narrow exceptions and one off-canon multiple-of-4 are inherited from the existing `DevApiStatus.tsx` so the new v3 blocks remain visually indistinguishable from the 8 v2 blocks already shipping in the same panel — see **Exceptions** below.

| Token | Value | Usage in this phase                                                               |
| ----- | ----- | --------------------------------------------------------------------------------- |
| 0.5   | 2px   | `mt-0.5`, `gap-0.5` — tight inline numerics inside a row (exception, see below)   |
| 1     | 4px   | `mt-1`, `gap-1`, `pt-1` — block content spacing                                   |
| 1.5   | 6px   | `gap-1.5`, `px-1.5` — callout pill padding (exception, see below)                 |
| 2     | 8px   | `mt-2`, `pt-2`, `p-2`, `gap-2` — block-to-block separation                        |
| 3     | 12px  | `px-3`, `gap-3` — section breaks / tab-button width parity (off-canon, see below) |
| 4     | 16px  | `px-4` — Topbar horizontal padding (existing)                                     |

Block separator: `mt-2 border-t border-white/10 pt-2` (used by every existing v2 block — copy verbatim for v3 blocks).

### Exceptions

The values **2px (token `0.5`)** and **6px (token `1.5`)** are **not** multiples of 4 and would normally be disallowed by the project's 8-point grid. They are admitted here as a **closed-set, copy-verbatim inheritance** from the existing `DevApiStatus.tsx` (1709 LOC, locked through 8 prior v2 phases). Substituting them with 4px or 8px would visually fork the new v3 blocks from the 8 v2 blocks living inches away in the same dashboard panel — that breaks this spec's core contract that "every spacing call must already match an existing class string in `DevApiStatus.tsx`."

These are Tailwind v4 default-scale utilities (`mt-0.5` = 2px, `gap-1.5` = 6px, etc.) and are load-bearing for visual continuity. The executor must use **only the exact same tokens that already appear in the file** — no new sub-grid micro-spacing is introduced.

**Cited precedents in `src/components/ui/DevApiStatus.tsx`** (grepped 2026-04-25):

| Token | Value | Existing usages (exhaustive in the existing v2 file)                                                                                                                                                                                                                                              |
| ----- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0.5` | 2px   | `gap-0.5` at lines 168, 180, 1354 (inline status-dot rows); `mt-0.5` at lines 433, 438, 451, 911, 941, 948, 953, 972, 1009, 1019, 1041, 1080, 1108, 1115, 1125, 1144, 1162, 1283, 1354, 1546, 1560, 1668, 1678 (sub-row offsets under headers); `space-y-0.5` at line 1354; `py-0.5` at line 1678 |
| `1.5` | 6px   | `gap-1.5` at line 152 (inline status-row gap); `p-1.5` at line 426 (callout pill padding); `px-1.5` at line 1678 (amber chip horizontal padding)                                                                                                                                                  |

**Closure rule.** The v3 blocks may use **only** `0.5` and `1.5` in the same shapes those tokens already occupy in v2 (gap, mt, p / px / py — never new directions like `space-x-0.5` or `m-1.5` if those don't already appear). If a v3 block needs a spacing value that is neither a canonical 4-multiple nor one of these two pre-existing tokens, the correct fix is to round to the nearest canonical token, **not** to introduce another sub-grid value.

**12px (token `3`) — multiple-of-4 but off-canon.** The value 12px is a clean multiple of 4 but is not in the declared canonical set `(4, 8, 16, 24, 32, 48, 64)`. It appears in `DevApiStatus.tsx` at line 316 (`px-3 py-1` on the existing `TabButton` — sets the dashboard's tab-button width and horizontal rhythm) and at lines 791 / 861 (`px-4 py-3` on the dashboard header / body wrappers). The v3 blocks may reuse `px-3` / `gap-3` **only** for section-break and tab-button parity with these existing patterns — never as a generic body spacing — so the new blocks line up with the existing tab strip on the same row.

## Typography

Dev dashboards are dense readouts. The project locks to **two sizes** (`text-[9px]` and `text-[10px]`) and **two weights** (`font-medium` 500, `font-bold` 700) inside DevApiStatus. **No new sizes are introduced.** Numeric columns use `tabular-nums` for monospace alignment without switching font family.

| Role            | Class                                                         | Computed         | Usage                                                 |
| --------------- | ------------------------------------------------------------- | ---------------- | ----------------------------------------------------- |
| Section header  | `text-[9px] font-bold uppercase tracking-wider text-white/40` | 9px / 700 / 1.5  | Every block heading (e.g. "Routing Trace", "Latency") |

## Interaction Contracts

### Data freshness

All v3 blocks read from the same `useLLMStatusPolling()` hook the v2 blocks already use. The hook polls `/api/events/llm-status` on the existing cadence (no change). New `LLMStatus` fields the executor must add to the hook's return type:

```ts
// Additive only; v2 callers ignore unknown fields
routingTrace?: Array<{ ts: number; batch: number; provider: FreeProvider; model: string; reason: string }>;
latency?: Record<FreeProvider, { p50: number; p95: number; p99: number; sparkline: number[] }>;
rateLimit?: Record<FreeProvider, { used: number; cap: number; window: 'minute' | 'day'; perModel?: Record<string, { used: number; cap: number }> }>;
schemaFailures?: Record<FreeProvider, { total: number; malformedJson: number; missingField: number; typeMismatch: number }>;
errorTaxonomy?: Record<FreeProvider, Record<'rate_limit' | 'timeout' | 'malformed_json' | 'schema_fail' | 'network' | 'upstream_500' | 'other', number>>;
pipelineFlips?: Array<{ ts: number; from: 'v1' | 'v2' | 'v3'; to: 'v1' | 'v2' | 'v3'; trigger: string; operator: string; reason?: string }>;
costShadow?: { tokensIn: number; tokensOut: number; usd: number };
schemaVersion?: 'v1' | 'v2' | 'v3' | 'unknown';
```

A9 mirror rule (project canon): when `LLMRunSummary` server interface adds these fields, `useLLMStatusPolling.ts` types update **in the same commit**.

### Empty-state behavior

Every block must render its empty-state line (see Copywriting table) when its corresponding `llmStatus.*` field is undefined or zero-length. **No block is hidden when empty**; this preserves the operator's mental map of "block X exists, just no data yet." Mirrors existing `CallLogBlock` and `DlqBlock` behavior.

- `drill-down-row-toggle` (existing) — keyboard activable (native `<button>`)
- `drill-down-copy` (existing) — keyboard activable
- `routing-trace-row-toggle` (new) — must be a native `<button>` with `aria-expanded`

No focus traps, no modal scrim added by this phase. The dashboard's modal scrim is a pre-existing concern.

### Auto-rollback discoverability

Per CONTEXT D-17, both auto-rollback triggers fire **without UI involvement**. The discoverability path for an operator is:

1. Topbar `PipelineVersionPill` shows `v2` (was `v3` before rollback).
2. `Pipeline Flips` block shows the new `auto:…` row at top of list.
3. Existing `DevApiStatusTrigger` may flip to `API !` red glyph if the rollback also degraded any connection (incidental, not a guaranteed signal).

**No toast notification** is added in this phase. Rationale: we already render a passive read-only pill and an audit block that surface every flip; introducing a toast adds a new UI primitive that doesn't exist elsewhere in the app.
