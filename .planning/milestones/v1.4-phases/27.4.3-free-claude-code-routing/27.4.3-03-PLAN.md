<objective>
Run the D-08 multi-model bake-off — exercise the v3 extractor against a candidate set of NVIDIA NIM models on the 50-event ground-truth corpus, record per-candidate scores, pick the winner closest to the 0.940 within20km baseline (subject to the D-16 Gate A 0.890 floor), and lock the winner in `freeClaudeRouter.NVIDIA_NIM_DEFAULT_MODEL`.

This plan is **non-autonomous** because the executor needs:

- A real `NVIDIA_NIM_API_KEY` exported in env (placeholder values from Plan 01 acceptance won't reach the live provider)
- Iterative judgment on which candidate models are actually available in NVIDIA NIM's catalog at execution time (the upstream catalog drifts — CONTEXT calls this "Claude's Discretion")
- A human-confirm step at the end before locking the winner (one-line config edit)

Per CONTEXT D-08 candidates in priority order:

1. `moonshotai/kimi-k2.5` — MoE, strong multilingual & structured output (best fit for Persian/Arabic place names)
2. `z-ai/glm4.7` — free-claude-code's default, recent (2025)
3. `meta/llama-3.3-70b-instruct` — known baseline for OSS reasoning
4. Whatever else NVIDIA NIM ships at execution time (planner picks)

CRITICAL DISTINCTION (per CONTEXT A6 + Pitfall 8): `runEval()` is RESOLVER-ONLY and does NOT call the LLM. The bake-off therefore requires running the full v3 extractor (`/api/events?force=true` with `LLM_PIPELINE_V3=true` + `modelOverride` plumbed) for each candidate to PRODUCE the enriched events, then running `npm run eval:replay -- --model=<id>` to score the resolver output against the GT corpus.

Output: `27.4.3-03-BAKEOFF.md` matrix + `freeClaudeRouter.NVIDIA_NIM_DEFAULT_MODEL` set to winner.
</objective>
