## Component Specifications

### `HealthBanner`

```tsx
// src/components/ui/HealthBanner.tsx (NEW in W2)

export interface HealthBannerProps {
  // No props — reads health from useHealthStatus() hook directly
  // (matches NotificationBell + StatusPanel pattern: components own their store/hook subscriptions)
}

export function HealthBanner(): JSX.Element | null;
```

**Internal state:**

- `acknowledged: Set<string>` — local React state, endpoint names dismissed in this session.
- `health` — read from `useHealthStatus()` hook (returns `{ health: HealthResponse | null, error: Error | null }`).

**Render rule:**

- Returns `null` if: `health == null` (initial load) OR no endpoint matches `tier === 'critical' && status === 'unhealthy' && !acknowledged.has(endpoint.name)`.
- Renders single banner if ≥1 critical endpoint matches.
- Banner content: severity label + comma-separated endpoint names + Dismiss button.

**ARIA:** `role="alert"` + `aria-live="assertive"` (critical-tier outage warrants assertive — interrupts screen readers).

**Auto-dismissal:** Banner clears automatically when all matching endpoints transition out of `unhealthy` (Set-based `acknowledged` resets implicit — endpoints not in current critical-unhealthy filter are removed from acknowledged via cleanup-effect). New unhealthy endpoint NOT in acknowledged → reappears.

**Manual dismiss:** Click Dismiss → all currently-displayed endpoint names added to `acknowledged`. Same endpoint going healthy then unhealthy again → reappears (because `acknowledged` is a session-level `Set`, but the next health-clearance cycle removes it).

**No persistent dismiss across page reloads.** Decision: session-level acknowledgement only. Rationale: persistent dismissal would silence ongoing outages — operators benefit from re-reminder on next session.

### `DevApiStatusAllApisTab`

```tsx
// inline component inside src/components/ui/DevApiStatus.tsx (or extracted to a sibling file)

export interface DevApiStatusAllApisTabProps {
  health: HealthResponse | null;
  loading: boolean;
  error: Error | null;
}

export function DevApiStatusAllApisTab(props: DevApiStatusAllApisTabProps): JSX.Element;
```

**Layout: table with 6 columns** (matches existing Overview tab table aesthetic at `DevApiStatus.tsx:369-407`):

| Column     | Width          | Content                                                                                                                                              | Sort default                                                           |
| ---------- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Endpoint   | flex (~30%)    | Endpoint name (e.g., `/api/flights`)                                                                                                                 | —                                                                      |
| Tier       | ~80px          | Outline pill: `CRITICAL` / `NON-CRITICAL` / `STATIC` / `PROBE` / `CRON`                                                                              | Primary sort: `critical → non-critical → static → probe-only → cron`   |
| Status     | ~80px          | Filled pill: `HEALTHY` / `DEGRADED` / `UNHEALTHY` / `UNKNOWN` (color per status enum above)                                                          | Secondary sort within tier: `unhealthy → degraded → unknown → healthy` |
| Freshness  | ~70px          | Relative `Xs` / `Xm` / `Xh` (using existing `formatAge()` from `DevApiStatus.tsx:71`); `--` for probe-only; absolute timestamp on hover via `title=` | Tertiary sort: largest-first within status                             |
| Latency    | ~60px          | `Xms` (right-aligned, tabular-nums); `--` if probe failed                                                                                            | —                                                                      |
| Last error | flex remainder | Truncated to 1 line; full text on row-expand                                                                                                         | —                                                                      |

**Group-by-tier:** Render a header row separator (`text-white/40 uppercase tracking-wider text-[9px] py-1 border-t border-white/10`) before each tier's rows. Five group headers in tier order.

**Row interaction:**

- Hover: `hover:bg-white/5` (matches Overview tab line 391).
- Click: expand row to show full last-error detail + raw `EndpointHealth` JSON in a `<pre>` block (matches `DevApiStatus.tsx:1421` expanded-row pattern).

**Threshold-breach visual cue:**

- When `freshnessMs > freshnessThresholdMs` (the `degraded`/`unhealthy` boundary), the Freshness cell renders with `text-accent-yellow` (degraded) or `text-accent-red` (unhealthy).
- No italic, no extra border — color carries the signal in concert with the explicit Status badge.

**Loading state (initial fetch):**

- 5 skeleton rows: `<div className="h-6 bg-white/5 animate-pulse rounded" />` × 5, one per tier group, no borders.

**Error state (poll failed entirely):**

- Single row: `<tr><td colSpan={6} className="text-center text-text-muted py-6">/api/health unreachable. Last successful poll {ageOfLastSuccess}.</td></tr>`
- If never successful: `/api/health unreachable since page load. Check server logs.`

**Empty state:**

- `health.endpoints` empty (deploy edge case): `<tr><td colSpan={6} className="text-center text-text-muted py-6">No endpoints configured.</td></tr>`
- Practically unreachable in this phase; included for total-state-coverage hygiene.

### `useHealthStatus`

```tsx
// src/hooks/useHealthStatus.ts (NEW in W2)

export function useHealthStatus(intervalMs?: number): {
  health: HealthResponse | null;
  loading: boolean; // true while initial fetch is in flight
  error: Error | null; // last poll error; null if last poll succeeded
  lastSuccessAt: number | null; // ms epoch of last successful poll
};
```

- Default `intervalMs = 60_000` (60s — research §Focus Area 7 explicit).
- Recursive `setTimeout` (matches `useFlightPolling` pattern from CLAUDE.md "Flight Data Patterns").
- Tab-visibility-aware: pauses polling when `document.hidden`; immediate fetch on `visibilitychange` → visible.
- On poll error: keeps last successful `health` (don't blank out UI), exposes `error`. Banner + tab continue rendering against last-known-good state with a stale-indicator cue (driven by `error != null` from caller).

### HealthBanner

| Trigger                                                             | Action                                                                                                                                                                                                       |

| Concern                            | Implementation                                                                                                                                                                                                                                                                                                                                             |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## Open Questions (require user / planner sign-off before W2 PLAN)

### Q1 (carryover from prompt Q13) — HealthBanner Bearer-gating

**Context:** D-26 locks the reaction tiers (critical = banner) but does not specify whether HealthBanner is operator-only (`shouldRenderDashboard()`-gated, like DevApiStatus) or visible to anonymous users.

**Recommendation: GATE behind `shouldRenderDashboard()`.**

Rationale:

1. The dashboard's primary anonymous audience is "show me real-time intelligence" — surfacing `/api/flights is unhealthy` to an anonymous user adds noise without giving them remediation power.
2. `/api/flights` going unhealthy is _already_ communicated to anonymous users via the StatusPanel's red `flights` dot — the banner becomes redundant for that audience.
3. The banner's value is operational: it tells the operator "go investigate" — operator is the only audience with the action capacity.
4. Gating preserves the cleaner anonymous experience documented in the project's portfolio framing (Phase 26.4 README rewrite).

**Alternative: not gated (visible to all).**

Pro: Public-facing transparency about data freshness; reinforces "numbers over narratives" honesty.
Con: Visual noise during incidents; no actionable signal for anonymous users.

**Decision needed before W2 PLAN.** This UI-SPEC defaults to gated (Recommendation above) unless overridden.

### Q2 — DevApiStatus tab label slot budget

**Context:** Adding a 5th tab (`All APIs`) to the existing 4 (`Overview`, `Water`, `Sites`, `Events`) brings tab strip width to ~5 × 60px = ~300px. Within the 92vw modal max-width (~960px on desktop) this fits comfortably; on narrow viewports (<720px), the tab strip may need horizontal scroll or to drop the trailing `Copy diagnostics` icon.

**Recommendation:** Accept the existing horizontal scroll behavior on narrow viewports (modal already overflows on mobile per "Mobile is not first-priority" in `<constraints>`). Do not redesign the tab strip in W2.

### Q3 — Initial sort within "All APIs" tab

**Context:** UI-SPEC locks tier-then-status-then-freshness sort. Confirm this matches operator scan pattern.

**Recommendation:** Keep proposed sort. Operator workflow: "Anything red? → if yes, which tier? → if no, anything yellow getting close to threshold?" The proposed sort matches this scan order.

### Q4 — Threshold-breach color cue strength

**Context:** UI-SPEC proposes coloring just the freshness cell on threshold breach. An alternative is a full row tint (e.g., `bg-red-950/30` for unhealthy rows).

**Recommendation:** Cell-only coloring. Full-row tint adds visual heaviness; the explicit Status pill is the row-level signal. Reserve heavy row tinting for catastrophic states (e.g., 5+ critical unhealthy simultaneously — backlog if observed in production).
