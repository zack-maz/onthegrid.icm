## What Was Built (concrete)

### Server-side `/api/health` handler

- **Dual-mounted** at `/health` (preserves the legacy back-compat caller surface) AND `/api/health` (the canonical D-22b/D-24 path that DevApiStatus + curl-based ops use). `server/index.ts` wires both mounts to the same `healthRouter`.
- **Per-endpoint freshness derivation** computes status against `FRESHNESS_THRESHOLDS_MS` (D-25). Each entry declares its own SLA — flights 60s, ships 120s, events 15min, news 15min, sites 24h, water 24h, etc.
- **W1 audit DRIFT-1/2/3 baked in** to `SOURCE_KEYS`: news now reads `news:feed` (DRIFT-1), sites reads `sites:v3` (DRIFT-2), water reads `water:facilities:v3` (DRIFT-3). DRIFT-4 (markets range suffix) documented inline — only the default `:1d` is probed.
- **D-26 tier classification** in `TIER_BY_ENDPOINT`: `critical | non-critical | static | probe-only | cron`. The handler groups results by tier in the response payload so DevApiStatus can render with tier headings.
- **Probe-strategy dispatch by endpoint kind:**
  - **cache-backed** — read `fetchedAt` from Redis `CacheEntry<T>` via `cacheGetSafe` (huge TTL = read-only)
  - **in-memory** — read store-side connection state (per-store `ConnectionStatus`) for hot polling endpoints
  - **config-derived** — derive freshness from environment / config (e.g. `/api/sources` is near-free)
  - **probe-only** — light direct adapter call (only used where cache-state is unavailable)
  - **cron-tick** — derive freshness from cron schedule + last-tick Redis key
- **Per-probe `withTimeout(2s)` cap** caps total response time and bounds DoS-burst risk (T-28.1-W2-02 mitigation).
- **`sanitizeError`** scrubs the `lastErrorReason` field before serialization — strips Bearer headers, `api_key=` query params, and full Upstash REST URLs (T-28.1-W2-01 mitigation, mirrors existing `server/lib/logger.ts` redact pattern).
- **Read-only contract preserved** — no cache writes from `/api/health`. Honors Phase 27.4.6 anti-pattern #17 (cache writes happen only in cron paths).
- **Zod-validation at the response boundary** — handler `.parse()`s the response object against `healthResponseSchema` before `res.json(...)` so any future drift fails loud at the route, not silently in the client.

### Client surfaces

- **`useHealthStatus`** — recursive `setTimeout(60_000)` (NOT `setInterval`, per CLAUDE.md flight pattern); `document.addEventListener('visibilitychange', ...)` pauses polling when the tab is hidden and triggers an immediate fetch when it becomes visible. Returns `{ health, loading, error, lastSuccessAt }`.
- **`HealthStatusProvider`** — wraps `useHealthStatus()` exactly once. Exposes the value to descendants via `useHealthStatusContext()`. Both `HealthBanner` and the `DevApiStatus` 'All APIs' tab body consume the context — they never call `useHealthStatus()` directly. This halves the outbound `/api/health` request rate vs the naive both-consumers-call-the-hook design (T-28.1-W2-02 mitigation).
- **`HealthBanner`** — sticky toast component. Returns `null` when all critical-tier endpoints are healthy. Renders the warning when ≥1 critical-tier endpoint becomes unhealthy. Renders within one poll cycle (60s default) of the cache transitioning to unhealthy. **Mounted UNCONDITIONALLY in `AppShell`** — NOT gated behind `shouldRenderDashboard()` (per user 2026-05-01 decision; UI-SPEC §Q1 default-recommendation explicitly overridden).
- **`DevApiStatus` 'All APIs' tab** — fifth tab body (after Overview / Water / Sites / Events). 6-column tier-grouped table (Endpoint, Tier, Status, Freshness, Latency, Last error). Sortable columns; rows have click-to-expand for the raw JSON payload row. Loading skeleton + error message states per UI-SPEC §State Visualization. `uiStore.activeDevApiStatusTab` enum extended with `'all-apis'`; `src/types/ui.ts` `DevApiStatusTab` union widened.

## Decisions Made

- **Dual-mount `/api/health` AND `/health`** rather than retiring `/health`. Preserves the existing back-compat caller surface (Vercel cron-health probe + any external monitor) while adding the canonical `/api/health` path that DevApiStatus + future ops tooling consume. Avoids a downstream renaming sweep.
- **`useHealthStatusContext` returns a safe default** (`{ health: null, loading: false, error: null, lastSuccessAt: null }`) when called outside `<HealthStatusProvider>` rather than throwing. Decision rationale: 45 pre-existing component tests render `HealthBanner` / `DevApiStatus` without a provider boilerplate; throwing would force retrofitting wrappers across all of them. The single-poll invariant is still enforced — statically — by the Task 5b grep audit which confirms `useHealthStatus()` is called from exactly one location (`HealthStatusProvider`).
- **Path B audit acceptance for live preview UAT.** The Vercel preview environment at `https://irt-monitoring-8h5932lsh-zack-mazs-projects.vercel.app` returns HTTP 500 / `FUNCTION_INVOCATION_FAILED` for ALL API routes because `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` are not configured for the preview environment. `server/config.ts` `parseEnv()` (introduced in commit `9b4af3a`, Phase 26.3 Plan 01, April 2026) is fail-fast Zod and throws at module-init when those creds are absent → every serverless invocation crashes. **This is NOT a W2 regression.** Production deploys are unaffected (creds present). User explicitly approved Path B (skip live UAT, accept local audit) on 2026-05-02. See "Known Limitations" below.
- **Three legacy `/health` test assertions updated in Task 2 GREEN.** `server.test.ts` (1 assertion), `vercel-entry.test.ts` (1 assertion), and `redis-death.test.ts` (1 assertion) needed to absorb the new HealthResponse shape. Bundled into the Task 2 GREEN commit because they are a direct downstream consequence of the route handler rewrite — keeping them in a separate commit would have left Task 2's GREEN failing in isolation, breaking strict TDD per-commit-must-pass invariant.
