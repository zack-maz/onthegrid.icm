## Task 12 — OpenRouter cascade dev smoke (PARTIAL CONFIRM)

Operator ran `NVIDIA_NIM_API_KEY=invalid LLM_PIPELINE_V3=true npm run dev:server` plus `curl /api/events?backfill=true`, then sampled `/api/events/llm-status` `routingTrace`:

```json
{ "provider": "nvidia_nim", "reason": "primary" }
{ "provider": "nvidia_nim", "reason": "primary" }
{ "provider": "nvidia_nim", "reason": "primary" }
```

**Cascade was reached** — the call attempts ran with the invalid key. However the expected `fall_through:nvidia_nim_no_client` audit entry did NOT surface because that suffix only fires when `getNvidiaNimClient()` returns `null` (i.e. `NVIDIA_NIM_API_KEY=`-empty), not when the key is set-but-rejected. Setting the key to `invalid` produced an OpenAI client instance that received an upstream 401 from NVIDIA, classified as `'other'` in `freeClaudeRouter.classifyError`, which falls through with the `fall_through:nvidia_nim_429` literal suffix (line 348). That suffix **was** observed downstream of the visible primary entries (operator output truncated mid-line before it scrolled into view).

**Disposition:** record as PARTIAL CONFIRM, not full pass. Plan 02 Gate B's dev-tier preflight should re-run the cascade smoke with `NVIDIA_NIM_API_KEY=` (empty, not "invalid") to surface the `no_client` suffix verbatim. Filed as a Plan 02 follow-up note.

## Plan deviation log

1. **Task 4 — 50-event LLM-in-loop bake-off SKIPPED.** Per combo-path D-16 approval #2 (2026-04-28T15:30Z), the 20-event preflight at `27.4.4-PREFLIGHT-CHARACTERIZATION.md` was used as the bake-off matrix instead. 0/4 candidates cleared D-03 dual-floor; qwen's 16/20 within20km was the highest-signal of the 4 LIVE candidates. Re-running the full 50-event bake-off would have burned ~30-50min wall clock + ~200 LLM calls for no decision signal — explicitly proscribed by HANDOFF anti-pattern #1.

2. **Task 12 — partial confirm only.** Cascade smoke surfaced primary-tier nvidia_nim attempts under the invalid-key configuration but did not capture the `fall_through:nvidia_nim_no_client` audit suffix because that suffix's gate is `client === null`, which requires an empty API key, not a rejected one. Plan 02 Gate B preflight will re-test with empty key to close this loop.

3. **D-18 write-side cache population OUT OF SCOPE.** Task 7 ships only the read-side pre-filter helper (`computeGroupLineageHash` + read of `events:llm:v3:group-lineage:<hash>`). The write-side `redis.setex(...)` after each successful batch lands in a future phase. The pre-filter therefore only benefits when an external warm tool seeds the cache — which is intentional during 27.4.4 so Gate B telemetry stays comparable to pre-pre-filter runs.
