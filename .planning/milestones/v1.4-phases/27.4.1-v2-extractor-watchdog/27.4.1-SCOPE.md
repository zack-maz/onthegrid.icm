# Phase 27.4.1 — V2 Extractor Watchdog + LLM Pipeline TS Cleanup

Lightweight scope document created at branch-opening time so the planner
(`/gsd-plan-phase 27.4.1`) has a clear input when we're ready to plan.

## Goal

Close out Phase 27.4's known P0 architectural defect (v2 extractor loses up
to 45 minutes of LLM work on any single hung Cerebras call) and clean up
20 pre-existing TypeScript errors in the v1 rollback extractor that Phase
27.4 did not absorb during its main scope.

## In-scope work

### 1. P0 — V2 extractor per-batch cache flush + timeout watchdog (primary)

**File:** `server/lib/llmEventExtractor.v2.ts` — main batch-processing loop.

**Current defect:** V2 extractor writes `events:llm:v2` Redis cache ONLY
after all 184 batches complete. One hung Cerebras call (observed at batch
133/184 on 2026-04-21) causes ~45 min of completed LLM work to be discarded
when the server is restarted.

**Fix shape:**

- Per-batch `cacheSetSafe('events:llm:v2', currentBuffer, TTL)` with
  accumulating writes after each successful batch
- Per-batch timeout watchdog: if a batch exceeds N seconds (e.g., 90), abort
  it, DLQ-route the group with `reason='timeout_watchdog'`, and continue
- Preserve graceful-degradation contract — user still gets partial v2 data
  even on provider flakiness

**Related files to audit for the same pattern:**

- `server/lib/llmEventExtractor.v1.ts` — check if v1 has the same defect
  (since it's the rollback path, fix it too or at least document that it's
  best-effort)
- `server/adapters/llm-provider.ts` — the `callLLM` cascade wraps providers
  but doesn't enforce an overall per-call timeout beyond the SDK's own

### 2. v1 extractor TS cleanup (bundled)

**File:** `server/lib/llmEventExtractor.v1.ts` — 20 `TS18048: possibly undefined`

- `TS2345: partial object not assignable` errors at lines 141-151, 248, 258,
  289, 296, 299, 302, 310.

**Root cause:** loops over LLM-extracted event arrays where the compiler
cannot prove the iteration value is defined under strict optional-property
checks. Types in `server/lib/llmSchema.ts` permit `undefined` on fields that
runtime logic treats as non-null after Zod parse.

**Fix approach (per original todo):** narrow types at the Zod parse boundary.
After `enrichedEventAny.parse()` returns, cast through a stricter interface
that exactly matches the non-optional shape the loops assume. One-file change
around the parse call.

**Why this belongs here:** the P0 watchdog fix touches the v2 extractor hot
path; while we're revisiting LLM pipeline code paths and have the context
paged in, cleaning up v1.ts costs ~30 min and closes a tracked tech-debt
todo (`phase-27-llm-pipeline-ts-debt.md`).

### 3. Quick wins (bundled)

**3a. `server/adapters/llm-provider.ts` line 232 TS error**

`TS2345: number | undefined not assignable to number`. Adjacent to the
LLM pipeline work, ~5 min fix (null-check or narrow the argument type at
the call site).

**3b. `src/__tests__/entityLayers.test.ts` — 1 color test fix**

Test `other is gray with red tint` expects `[190,170,168]` but code returns
`[220,100,90]` (color changed in Phase 27 commit `709fa15`). ~1 min fix —
update test expectation to match the current color OR revert the color
change, depending on which is canonical. Canonical is the current code
value (27 shipped with it), so update the test.

**3c. Strip click-to-swap from `PipelineVersionPill` — keep indicator**

File: `src/components/layout/Topbar.tsx` — `PipelineVersionPill` component.

Current behavior: dev-only dotted pill shows `v1` amber / `v2` green;
clicking POSTs to `/api/events/llm-pipeline` to swap the runtime override.

Target behavior: same visual indicator (dot + label), but read-only. Click
handler removed. The pill becomes a passive "which version's data am I
seeing right now?" signal.

The `GET`/`POST /api/events/llm-pipeline` endpoints stay — they're still
useful for scripted/operator-level swaps. Env var `LLM_PIPELINE_V2` remains
the authoritative default. Only the UI toggle surface is removed.

Effort: ~15 min (remove onClick, remove optimistic-update local state,
trim any related tests).

Rationale: runtime toggling via UI is an operator-only workflow, not a
daily-dev one. Reducing the UI surface removes a misuse footgun (dev
accidentally swaps to v1 and forgets to swap back) while preserving the
observability value of knowing what's being served.
