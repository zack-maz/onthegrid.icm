## Follow-ups ranked by priority

### P0 — v2 extractor incremental cache flush + watchdog

**The one structural defect.** V2 extractor writes to `events:llm:v2` only AFTER all 184 batches complete. One hung Cerebras call loses 45+ minutes of LLM work (Cerebras tokens already billed).

**Fix shape:**

- Per-batch `cacheSetSafe('events:llm:v2', currentBuffer, TTL)` with accumulating writes
- Per-batch timeout: if a batch takes > N seconds (e.g., 90), abort that batch (DLQ it with reason=`timeout_watchdog`) and continue
- Honors graceful-degradation contract — user still gets partial v2 data

**File:** `server/lib/llmEventExtractor.v2.ts`, the main for-loop.

## Known gotchas

- **Node `--watch` doesn't reload `.env` changes.** Any env edit requires manual server restart. TS file edits DO reload.
- **Cerebras free tier rate limits:** we saw 60s+ response times during the v1 run; Cerebras's "high traffic" error is returned on some plain calls. Queue-based throttling.
- **Fire-and-forget extractor does NOT support concurrent runs:** `llmProgress.stage !== 'idle'/'done'/'error'` guard skips subsequent triggers until the current run completes. A stuck run therefore prevents new runs until server restart.
- **Cerebras API key was echoed in chat history** during debug (visible in commit `191708f` discussion — not a leak to external systems, but consider rotating as hygiene).
- **dev server runs on port 3001.** Vite on port 5173 proxies to it.
- **Worktrees `agent-a0b677f0`, `agent-a8acaba4`, `agent-afdc7d93`, `agent-a73bf500`, `agent-af68ec64`, `agent-a43fc75d`, `agent-a6e1ed19`, `agent-a3d117da` — 8 total, all locked by Claude harness.** Auto-clean at session end. If they persist, `git worktree remove <path> --force-force`.
