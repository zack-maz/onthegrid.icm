## Per-Store Retry Mechanic Audit (Task 5)

Audited all 9 polling stores for `fetchNow()` / `refreshNow()` actions before drafting the retry button. **Finding:** NO store currently exposes such an action. All stores follow the same `recentFetches: FetchRecord[]` append pattern but have no imperative fetch trigger. Resolution: cache-bust query-param fallback for all 9 stores.

| Store   | `fetchNow()` exposed? | Retry mechanic chosen                           |
| ------- | --------------------- | ----------------------------------------------- |
| Flights | No                    | `fetch('/api/flights?_ts=...')` cache-bust      |
| Ships   | No                    | `fetch('/api/ships?_ts=...')` cache-bust        |
| Events  | No                    | `fetch('/api/events?_ts=...')` cache-bust       |
| Sites   | No                    | `fetch('/api/sites?_ts=...')` cache-bust        |
| News    | No                    | `fetch('/api/news?_ts=...')` cache-bust         |
| Markets | No                    | `fetch('/api/markets?_ts=...')` cache-bust      |
| Weather | No                    | `fetch('/api/weather?_ts=...')` cache-bust      |
| Water   | No                    | `fetch('/api/water?_ts=...')` cache-bust        |
| Precip  | No                    | `fetch('/api/water/precip?_ts=...')` cache-bust |

The store's own polling cycle picks up the fresh cache on its next tick. Per CLAUDE.md (D-23) the retry MUST NOT bust LLM cache keys — `ENDPOINT_RETRY_PATH` map intentionally omits any `/llm-replay` or `events:llm:v3` URL. Test 14 codifies this contract via fetch spy.
