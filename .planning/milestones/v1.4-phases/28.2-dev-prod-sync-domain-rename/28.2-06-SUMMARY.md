## B-6 Target Switch Confirmation

`src/__tests__/rate-limit.test.ts` targets `/api/health` (NOT the flights route). Verify gate `! grep -n "/api/flights" src/__tests__/rate-limit.test.ts` passes (0 matches in test code; comment text references `the flights route` instead of the literal `/api/flights` token to keep the grep guard clean).

Rationale: the flights route has its own 120/min per-endpoint cap that triggers BEFORE the 60/min global tier. A 429 there does NOT unambiguously prove `rateLimiters.public` (Plan 02's surface) is firing. `/api/health` has NO per-endpoint cap; only the global tier applies. A 429 there proves the global tier — exactly the D-30 contract.

## Decisions Made

- **NEW `/api/audit-status` route, not /api/health extension** — keeps optional CI-fed metadata separate from critical-tier observability. Adding to HealthResponse Zod would churn every consumer (HealthBanner, DevApiStatus, useHealthStatus).
- **No auth gate on `/api/audit-status`** — operator-tier metadata is non-secret; global 60/min rate limit suffices.
- **Manual `workflow_dispatch` trigger only** — safer baseline when secrets are involved; future phase may promote to PR-trigger or scheduled.
- **Sidecar key written by GH Actions via Upstash REST API** — separates write-auth from read surface, avoiding the need for a write-auth gate on the server.
- **Test files skip by default** — opt-in via `RUN_CONNECTIVITY_TEST=1` / `RUN_RATE_LIMIT_TEST=1` env flags so regular `npx vitest run` doesn't fire 70+ HTTP requests against possibly-not-running localhost.
- **Local-dev audit pre-flight DEFERRED to operator** — D-25 explicitly says local is optional; gating evidence is the prod-URL run captured at Task 9.
