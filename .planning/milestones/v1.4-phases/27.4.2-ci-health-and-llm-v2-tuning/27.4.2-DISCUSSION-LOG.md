## Hang-Recurrence Policy

### Q1: What trigger qualifies as 'hang recurrence' during a tuning run?

| Option                                 | Description                                                                                        | Selected        |
| -------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------- |
| watchdogTimeoutCount ≥ 3 in single run | Tolerates isolated transient hangs (~1.6% noise floor at 184 batches), flags sustained recurrence. | ✓ (Recommended) |
| Any single watchdogTimeoutCount ≥ 1    | Aggressive zero-tolerance; halts on recoverable provider blips.                                    |                 |
| watchdogTimeoutCount/totalBatches > 5% | Ratio-based; ~9 timeouts before tripping.                                                          |                 |

**User's choice:** watchdogTimeoutCount ≥ 3 in single run

### Q2: When the trigger fires, what's the first response?

| Option                                                | Description                                                                           | Selected        |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------- | --------------- |
| Auto-flip Cerebras out of primary, retry Groq-first   | Provider order [groq, cerebras] for rest of wave. Continues with degraded throughput. | ✓ (Recommended) |
| Abort tuning iteration, surface DLQ for manual review | Cleanest signal but loses in-flight work.                                             |                 |
| Lower LLM_BATCH_TIMEOUT_MS to 60000 mid-run           | Tighter watchdog; increases false-positive DLQ rate.                                  |                 |

**User's choice:** Auto-flip Cerebras out of primary

### Q3: How do hangs interact with eval baseline capture?

| Option                                              | Description                                                                                     | Selected        |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------- | --------------- |
| Baseline must complete with watchdogTimeoutCount=0  | Cleanest baseline; retry until clean. Ground-truth replay (resolver-only) makes this practical. | ✓ (Recommended) |
| Baseline tolerates timeouts; record alongside score | Pragmatic if Cerebras hang is chronic. +5pp becomes noisier.                                    |                 |
| Baseline runs both v1 and v2 in same window         | Most rigorous A/B but doubles token spend on tight free tiers.                                  |                 |

**User's choice:** Baseline must complete with watchdogTimeoutCount=0

## Tuning Levers + Success Metric

### Q1: Which distance gate counts for the '+5pp over v1' success criterion?

| Option                                  | Description                                                                      | Selected |
| --------------------------------------- | -------------------------------------------------------------------------------- | -------- |
| 20km only (existing D-25 deploy gate)   | Matches production-flip threshold; right granularity for event monitor.          |          |
| 5km only (precision)                    | Sub-neighborhood; may not be reachable with prompt/threshold tuning alone.       |          |
| 100km only (regional)                   | Too loose; not where users feel the win.                                         |          |
| All three (5/20/100km), ratchet on 20km | Track all three; gate success on 20km. Catches regressions at finer granularity. | ✓        |

**User's choice:** All three (5/20/100km), ratchet on 20km

### Q2: How do we measure fallback<25% versus eval score?

| Option                                                 | Description                                                                                               | Selected        |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- | --------------- |
| Eval=ground-truth replay; fallback=full production run | runEval() is fast/deterministic; provenanceCounts requires real GDELT. Fast inner loop + slow outer loop. | ✓ (Recommended) |
| Both metrics from one full production run              | Each iteration costs a full run; cadence becomes daily not hourly.                                        |                 |
| Both metrics from ground-truth replay                  | Cheap but loses fidelity — GT skews toward Branch 1–3 hits.                                               |                 |

**User's choice:** Eval=ground-truth replay; fallback=full production run

### Q3: Tuning lever priority ranking — where to start?

| Option                                        | Description                                                                     | Selected        |
| --------------------------------------------- | ------------------------------------------------------------------------------- | --------------- |
| POI keyword expansion + amenity-mapping audit | Branch 2 highest-leverage for fallback reduction. §12 Q5 hypothesis.            | ✓ (Recommended) |
| 2-pass verify thresholds (250km/precision)    | Branch 4 reranker triggers. WR-04 single-candidate review.                      | ✓               |
| System prompt tightening                      | SYSTEM_PROMPT_V2 lines 84–114. Affects extraction → hierarchy → resolver depth. | ✓               |
| NEWS/TEMPORAL/BELLINGCAT block tuning         | §12 Q1–Q4. Lower-leverage on resolver fallback; save for later.                 | ✓               |

**User's choice:** All four selected (multi-select)
**Notes:** Priority order in CONTEXT D-11: POI → 2-pass → prompt → blocks. Each lever runs as a separate plan; D-13 goal-driven stop may close the wave before all four are touched.

### Q4: Tuning iteration cadence — micro or batched?

| Option                                            | Description                                    | Selected        |
| ------------------------------------------------- | ---------------------------------------------- | --------------- |
| Micro-iteration: one lever, GT replay, commit     | Maximum signal per iteration; trivial bisect.  | ✓ (Recommended) |
| Batched: 3-4 levers, single production run        | Fewer expensive runs; harder to attribute.     |                 |
| Big-bang: all selected levers, single measurement | Lowest token cost; can't bisect on regression. |                 |

**User's choice:** Micro-iteration

### Q5: Tuning wave time-box — how to bound the work?

| Option                                    | Description                                          | Selected        |
| ----------------------------------------- | ---------------------------------------------------- | --------------- |

| Wall-clock cap (3 production runs, ~2hrs) | Hard time-box; ships whatever's achieved.            |                 |

**User's choice:** Stop when both criteria are met

### Q6: Per-lever revert policy on GT regression?

| Option                                        | Description                                                           | Selected        |
