**Key decision points:**

- **Skip cache**: `shouldRunLLM()` (15-min cooldown) gates entire pipeline
- **Cooldown**: `events:llm-process-ts` tracks last run timestamp
- **In-flight guard**: `llmProgress.stage !== 'idle'` prevents concurrent runs
- **Pitfall 1 bridge**: v2 reads v1 cache when terminal key is empty (rollout safety)
- **Partial cache (D-09)**: `events:llm:v2:partial` holds envelopes for /llm-status observability only; users never see this
- **Terminal cache (D-09)**: `events:llm:v2` holds ConflictEventEntity[] and is only written after geocoding completes

- `events:llm:v2` — **terminal key**, written ONCE after geocoding + eval complete, holds clean `ConflictEventEntity[]`

### 3. Zod Schema v2 Shape

```typescript
// llmSchema.ts — LocationHierarchyV2 (STRICT mode)
export const locationHierarchyV2 = z.object({
  country: z.string().min(1).nullable(),        // "Iran", "Iraq", null
  admin1: z.string().min(1).nullable(),         // province/state name
  city: z.string().min(1).nullable(),           // city/town name

  targetType: z.enum(['military', 'infrastructure', 'civilian', 'leadership']).nullable(),             // ← D-13
  timeOfDay: z.string().regex(/^([01]\d|2[0-3]):[0-5]\d$/).nullable(),  // ← D-14 HH:MM
  durationMinutes: z.number().int().nonnegative().nullable(),           // ← D-14 minutes
  actors: z.array(z.string()),
  severity: z.enum(['critical', 'high', 'medium', 'low']),
  summary: z.string(),
  casualties: z.object({
    killed: z.number().int().nullable(),
    injured: z.number().int().nullable(),
    unknown: z.boolean(),
  }),
  sourceCount: z.number().int(),
}).strict(); // ← No additional fields allowed

// Discrimination: enrichedEventAny = discriminatedUnion(['schemaVersion', [v1, v2]])
// Used on every cache read so mixed v1+v2 payloads parse during rollout (D-40 window)

// Server-side derived: precision = derivePrecision(hierarchy)
export function derivePrecision(hierarchy: LocationHierarchyV2): Precision {
  if (hierarchy.landmark !== null) return 'exact';
  if (hierarchy.neighborhood !== null) return 'neighborhood';
  if (hierarchy.city !== null) return 'city';
  return 'region'; // admin1-only and country-only both collapse to 'region'
}

// Suspect derivation: deriveSuspect(confidence, precision, distance, tiers)
export function deriveSuspect(input: SuspectInput): boolean {
  if (input.confidence < 0.5) return true;         // low LLM certainty
  if (input.precision === 'region') return true;   // coarse geography
  if (input.actionGeoDistanceKm > 100) return true; // spatial outlier
  if (input.tiers.length > 0 &&
      input.tiers.every((t) => t === 'bronze')) return true; // all weak sources
  return false;
}
```

- **D-05 enforcement:** `.strict()` on location object rejects any lat/lng/coordinates keys
- **Pitfall 4:** `schemaVersion` added via `z.preprocess` so LLM never emits it
- **Pitfall 5:** `precision` NOT on LLM output; server derives it from deepest non-null field
- **Commit a2ad342:** reasoning field uses `.transform()` truncation instead of `.max()` rejection (Cerebras doesn't support maxLength keyword)
- **Commit 8d325ee:** JSON schema removed `maxLength: 200` from reasoning wire field (Cerebras rejects unknown keywords)

### 4. Six-Path Resolver Hierarchy

All paths call `resolveLocation(hierarchy: LocationHierarchyV2, ctx: ResolveContext): Promise<ResolvedLocation>`. Order is strict priority; first match wins.

#### **Branch 1: own-site-snapshot**

- **Entry condition:** landmark is non-null
- **Logic:** `resolveFromSnapshot()` — fuzzy-name-match landmark against committed snapshots (sites.json + water.json)
- **Failure mode:** no match → continue to next branch
- **Provenance tag:** `'own-site-snapshot'`
- **Example:** landmark="Natanz nuclear enrichment complex" matches sitesSnapshot entry with label "Natanz" (fuzzyNameMatch checks substring + reverse)
- **No network call, no Redis access**

#### **Branch 2: poi-amenity-nominatim** (Plan 05 D-03)

- **Entry condition:** `isPoiLandmark(landmark)` returns true (checks POI_KEYWORDS: nuclear, airbase, naval base, airport, dam, refinery, power plant, pipeline, substation, port, etc.)
- **Logic:**
  ```typescript
  amenity = inferAmenity(landmark); // e.g., "nuclear" → "nuclear power plant"
  countryCode = countryCodeFromName(hierarchy.country); // e.g., "Iran" → "ir"
  candidates = await forwardGeocodeConstrained(landmark, {
    amenity, // ← Nominatim amenity parameter (mutually exclusive w/ q)
    countrycodes: cc ?? ME_COUNTRY_CODES, // ← D-02 constraint
    viewbox: ME_VIEWBOX, // ± viewbox bounding
    limit: 3,
    addressdetails: true,
  });
  filtered = candidates.filter((c) => !cc || c.address?.country_code === cc);
  return first || null;
  ```
- **Throttle:** WR-01 — `throttleNominatim()` fires AFTER cache-miss confirmed (so cache hits don't update timestamp)
- **Cache key:** `geocode:fwd:constrained:poi:${amenity}|${country}|${landmark}` (30d TTL, hit returns miss marker on no-match)
- **Failure mode:** no POI match, no candidates, or Nominatim error → continue
- **Provenance tag:** `'poi-amenity-nominatim'`

#### **Branch 3: nominatim-direct** (Plan 05)

- **Entry condition:** always reachable (fallthrough from POI)
- **Logic:**
  ```typescript
  query = buildDisplayNameForQuery(hierarchy) // join [landmark, neighborhood, city, admin1, country]
  if (!query) continue to Branch 4
  candidates = await forwardGeocodeConstrained(query, {
    countrycodes: cc ?? ME_COUNTRY_CODES,
    viewbox: ME_VIEWBOX,
    limit: 1,  // ← Single candidate, no reranking needed
  })
  return first || null
  ```
- **Throttle:** WR-01 applies
- **Cache key:** `geocode:fwd:constrained:direct:${query}|${country}`
- **Failure mode:** no candidates → continue
- **Provenance tag:** `'nominatim-direct'`

#### **Branch 4: nominatim-verified-2pass** (Plan 05 D-04)

- **Entry condition:** triggered only when:
  ```typescript
  directHit !== null && shouldTriggerTwoPassVerify(hierarchy, directHit, ctx);
  // where shouldTriggerTwoPassVerify = true if:
  //   precision === 'region' || precision === 'city' || distance > 250km
  ```
- **Logic:**

  ```typescript
  candidates = await forwardGeocodeConstrained(query, {
    limit: 5,          // ← Top-5 candidates
    addressdetails: true,
  })
  if (candidates.length === 1) return first (WR-04: auto-accept, skip LLM)

  userPrompt = buildRerankerUserPrompt(hierarchy, candidates, ctx)
  // Pass hierarchy + event summary + article titles to reranker

  raw = await callLLM([
    {role: 'system', content: RERANKER_SYSTEM_PROMPT},
    {role: 'user', content: userPrompt},
  ], RERANKER_JSON_SCHEMA)

  validated = rerankerResponseSchema.safeParse(JSON.parse(raw))
  // Expected: {pick: 1-5, reasoning: <=100 chars}

  return candidates[validated.data.pick - 1]
  ```

- **Throttle:** WR-01 applies to the 5-candidate fetch
- **LLM call:** new `callLLM` invocation (separate from main extractor batch); retries within its own budget
- **Cache key:** `geocode:fwd:constrained:verify:${query}|${country}`
- **Failure mode:** Nominatim returns 0, LLM fails, Zod parse fails → continue
- **Provenance tag:** `'nominatim-verified-2pass'`
- **Sanity gate (250km):** prevents confirming obviously-wrong (and expensive) Nominatim hits

#### **Branch 5: bellingcat-coord-passthrough** (W2 fix)

- **Entry condition:** `ctx.bellingcatCoord !== null` (set if article titles carried parseable lat/lng via extractBellingcatGeo)
- **Logic:**
  ```typescript
  return {
    lat: ctx.bellingcatCoord.lat,
    lng: ctx.bellingcatCoord.lng,
    displayName: 'Bellingcat-reported coordinate',
    provenance: 'bellingcat-coord-passthrough',
  };
  ```
- **Failure mode:** cannot fail (pure return)
- **Provenance tag:** `'bellingcat-coord-passthrough'`
- **Threading (W2 fix):** ctx.bellingcatCoord populated in fire-and-forget block via `bellingcatByGroup.get(ev.groupKey)`

#### **Branch 6: gdelt-actiongeo-fallback** (final)

- **Entry condition:** all prior branches failed or unreachable
- **Logic:**
  ```typescript
  return {
    lat: ctx.centroidLat, // ← group.centroidLat from GDELT
    lng: ctx.centroidLng, // ← group.centroidLng from GDELT
    displayName: 'GDELT ActionGeo centroid',
    provenance: 'gdelt-actiongeo-fallback',
    actionGeoDistanceKm: 0, // ← distance to self
  };
  ```
- **No network call, no cache access**
- **Provenance tag:** `'gdelt-actiongeo-fallback'`

**Nominatim throttle (1 req/s):**

- Module-level `lastNominatimCallMs` tracks last call timestamp
- `throttleNominatim()` sleeps `max(0, 1000 - elapsed)` before updating the timestamp
- **WR-01 optimization:** throttle fires AFTER cache-miss confirmed, so a cache-hit does not consume a request slot
- **Test reset:** `__resetThrottleForTests()` clears timestamp for test isolation

**Single-candidate auto-accept (WR-04):**

- `resolveViaVerifiedTwoPass()` line 392-405: if fetching top-5 Nominatim returns exactly 1 candidate, accept it without LLM reranking
- Rationale: single unambiguous result needs no disambiguation
- Does NOT cache a miss (which would wrongly route future same-query to fallback)

**250km sanity gate:**

- `shouldTriggerTwoPassVerify()` line 356: if `directHit` is >250km from centroid, trigger reranker
- Rationale: avoid confirming wildly-distant Nominatim hits; LLM reranker sees full candidate set and can pick a closer alternative
- If reranker also fails, Branch 3's `directHit` is accepted anyway (graceful fallback)

### 5. Reliability Primitives

#### **Watchdog (Phase 27.4.1 D-01/D-02/D-04/D-05/D-06)**

File: `server/lib/llmExtractorWatchdog.ts`

```typescript
export interface BatchWatchdogOptions {
  timeoutMs: number; // D-01: hard kill (env LLM_BATCH_TIMEOUT_MS, default 90000)
  softWarnMs: number; // D-02: amber marker (hard-coded 60000)
  batchIndex: number;
  label: string; // 'v1' | 'v2'
  onTimeout: () => Promise<void>; // D-04: DLQ-route batch + progress bump
  onSoftWarn?: (elapsedMs: number) => void; // D-02: synthetic callHistory entry
}

export async function withBatchWatchdog<T>(
  batchFn: () => Promise<T>,
  opts: BatchWatchdogOptions,
): Promise<T | null>;
```

- **Soft-warn (D-02):** at 60s elapsed, call `onSoftWarn(60000)` which appends synthetic entry to callHistory:

  ```typescript
  { provider: 'cerebras', model: 'watchdog-soft-warn', tokensIn: 0, tokensOut: 0,
    durationMs: 60000, ok: true, batchSize: N, timestamp: now }
  ```

  DevApiStatus renders this as an amber marker on the call log so operators see the batch is slow.

- **Hard timeout (D-01):** at 90s (env-tunable), `Promise.race` rejects; watchdog catches and:
  1. Sets `timedOut = true` (late-resolve guard)
  2. Awaits `onTimeout()` → DLQ-enqueue each group in batch w/ reason='timeout_watchdog'
  3. Updates `llmProgress.watchdogTimeoutCount++`
  4. Returns `null` to caller

- **Late-resolve guard (D-05):** if batch promise resolves AFTER hard timeout fires:
  - `timedOut` flag prevents `onTimeout()` re-invocation
  - `.catch(() => {})` on workPromise swallows late rejection
  - Caller receives `null` (not clobbered by late value)

- **Synthetic callHistory entries (D-04):**
  - `timeout_watchdog` entries appear in `/llm-status` call log
  - `soft-warn` entries show amber markers (not failures, but slow)

- **Budget states:**

- **Severity reordering (D-35):** `prioritizeBySeverity()` reorders groups so BATCH_SIZE slice contains highest-severity events when soft-capped
- **Skipped attempt recording (D-19):** when a provider is skipped (breaker/hard_cap/no_client), a synthetic callHistory entry is appended with `skipReason` field for DevApiStatus diagnosis

#### **Integration into callLLM**

```typescript
export async function callLLM(
  messages: OpenAI.Chat.ChatCompletionMessageParam[],
  jsonSchema: Record<string, unknown>,
  opts: { batchSize?: number } = {},
): Promise<string | null> {
  const providers: Provider[] = ['cerebras', 'groq'];

  for (const provider of providers) {
    if (!isAvailable(provider)) {  // ← Circuit breaker check (D-31)
      recordSkippedAttempt(provider, batchSize, 'breaker');
      continue;
    }

    const used = await getDailyTokens(provider);
    if (budgetState(provider, used) === 'hard') {  // ← Hard cap check (D-34)
      recordSkippedAttempt(provider, batchSize, 'hard_cap');
      continue;
    }

    for (let attempt = 0; attempt < RETRY_ATTEMPTS; attempt++) {  // 2 attempts
      try {
        const result = await tryProviderOnce(provider, messages, jsonSchema, batchSize);
        if (result.content) {
          record(provider, 'ok');  // ← Record success for circuit breaker
          await incrDailyTokens(provider, result.tokens);  // ← D-32: token increment
          appendCallHistory({...});  // ← D-19: callHistory entry
          updateProgress({tokenCounters, breakerState});  // ← D-32/D-31: update progress
          return result.content;
        }
        break;  // null content, don't retry same provider
      } catch {
        record(provider, 'err');  // ← Record failure for circuit breaker
        if (attempt < RETRY_ATTEMPTS - 1) {
          await sleepWithJitter(BACKOFF_MS[attempt] ?? BACKOFF_MS[0]);  // [1s, 4s]
        }
      }
    }
  }

  return null;  // ← Graceful degradation to raw GDELT (D-29)
}
```

### 6. Batch Loop Mechanics (v2 Only)

```typescript
export const BATCH_SIZE = 2;  // D-10 — reduced from v1's 8

export async function processEventGroupsV2(
  groups: EventGroup[],
  onBatchComplete?: (completed: number, total: number) => void,
): Promise<V2ExtractionRun> {
  const results: EnrichedEventV2[] = [];
  const totalBatches = Math.ceil(groups.length / BATCH_SIZE);

  for (let i = 0; i < groups.length; i += BATCH_SIZE) {
    const batch = groups.slice(i, i + BATCH_SIZE);  // 1-2 groups per batch
    const batchIndex = Math.floor(i / BATCH_SIZE);

    // ============================================================
    // STAGE 1: Parallel Redis reads for enrichment context
    // ============================================================
    const contexts = await Promise.all(batch.map(buildPromptContext));
    // buildPromptContext per group:
    //   - Read news:gdelt (±24h window, no haversine) → NEWS BLOCK
    //   - Extract Bellingcat coords from article titles via extractBellingcatGeo()
    //   - Load TEMPORAL CONTEXT from events:llm:v2 (±72h ±1deg, ≤3 events)

    // Hoist per-group metadata for downstream resolver
    for (const ctx of contexts) {
      matchedNewsByGroup.set(ctx.group.key, ctx.matchedNews);
      if (ctx.bellingcatHits[0]) {
        bellingcatByGroup.set(ctx.group.key, {
          lat: ctx.bellingcatHits[0].lat,
          lng: ctx.bellingcatHits[0].lng,
        });
      }
    }

    // ============================================================
    // STAGE 2: Assemble user prompt with 3 enrichment blocks
    // ============================================================
    const userPrompt = buildBatchUserPromptV2(contexts);

    // Prompt structure:
    // "Analyze these GDELT event groups and extract structured data:\n"
    //
    // --- Event Group 1 (key: grp-19000-17-0) ---
    // Date: 2026-04-21
    // CAMEO Code: 174
    // Location (GDELT ActionGeo): Tehran, Iran
    // Actors: Iran vs Israel
    // Goldstein Scale: -10
    // Total Mentions: 45, Total Sources: 12
    // Rows in group: 7
    // Source URLs: https://al-jazeera.com/..., ...
    //
    // --- NEWS BLOCK (tier-tagged) ---
    // [T1] Airstrike reported on nuclear facility
    // [T2] Israel claims strike success
    // [T3] Iran denies major damage
    //
    // --- BELLINGCAT OSINT (high-trust) ---
    // Satellite image shows crater at coordinates [Bellingcat coord hint: 35.67, 51.43]
    //
    // --- TEMPORAL CONTEXT (2 recent events in region) ---
    // - Isfahan (3h ago): Facility reported under attack, 5 casualties
    // - Qom (12h ago): Surface-to-air activity detected

    // ============================================================
    // STAGE 3: Call LLM with watchdog timeout protection
    // ============================================================
    const content = await withBatchWatchdog(
      () =>
        callLLM(
          [
            { role: 'system', content: SYSTEM_PROMPT_V2 },
            { role: 'user', content: userPrompt },
          ],
          EVENT_EXTRACTION_SCHEMA_V2,
          { batchSize: batch.length },
        ),
      {
        timeoutMs: env.LLM_BATCH_TIMEOUT_MS,  // 90s default
        softWarnMs: 60_000,
        batchIndex,
        label: 'v2',
        onTimeout: async () => {
          for (const g of batch) {
            await enqueueDLQ({
              id: g.key,
              reason: 'timeout_watchdog',
              lastError: `v2 batch ${batchIndex} exceeded ${env.LLM_BATCH_TIMEOUT_MS}ms`,
              timestamp: Date.now(),
            });
          }
          updateProgress({
            watchdogTimeoutCount: (llmProgress.watchdogTimeoutCount ?? 0) + 1,
          });
        },
        onSoftWarn: (elapsedMs) => {
          const entry: ... = {
            provider: 'cerebras',
            model: 'watchdog-soft-warn',
            tokensIn: 0, tokensOut: 0, durationMs: elapsedMs, ok: true, batchSize: batch.length,
            timestamp: Date.now(),
          };
          updateProgress({
            callHistory: [entry, ...history].slice(0, 20),  // Keep last 20
          });
        },
      },
    );

    if (content === null) {
      // Batch failed: watchdog timeout or callLLM returned null (providers unavailable)
      // Already DLQ'd / progress updated in watchdog or callLLM
      onBatchComplete?.(batchIndex + 1, totalBatches);
      await writePartialCache(results, batchIndex + 1, totalBatches, false);
      continue;
    }

    // ============================================================
    // STAGE 4: Parse + validate response
    // ============================================================
    try {
      const parsed = JSON.parse(content);
      const validated = batchResponseV2.safeParse(parsed);

      if (!validated.success) {
        // Zod fail: DLQ-route each group, log, continue
        const errPayload = JSON.stringify(validated.error.issues.slice(0, 3));
        for (const g of batch) {
          await enqueueDLQ({
            id: g.key,
            reason: 'zod_fail',
            lastError: errPayload,
            timestamp: Date.now(),
          });
        }
        onBatchComplete?.(batchIndex + 1, totalBatches);
        await writePartialCache(results, batchIndex + 1, totalBatches, false);
        continue;
      }

      // Validation passed: append to results
      results.push(...validated.data.events);
      allFailed = false;  // Mark run as having ≥1 success
    } catch (err) {
      // JSON.parse threw: non-fatal, skip batch
      log.warn({ err, batchIndex }, 'JSON.parse failed');
    }

    onBatchComplete?.(batchIndex + 1, totalBatches);

    // ============================================================
    // STAGE 5: Write partial snapshot for observability
    // ============================================================
    await writePartialCache(results, batchIndex + 1, totalBatches, false);
    // Writes to events:llm:v2:partial (NOT the terminal key)
    // Payload: {events: EnrichedEventV2[], progress: "N/M", complete: false}
    // Uses cacheSetSafe (Redis failure swallowed, memCache fallback)
  }

  // ============================================================
  // FINAL: Write completion snapshot, return run result
  // ============================================================
  await writePartialCache(results, totalBatches, totalBatches, true);
  // Final write: complete: true so /llm-status knows run finished

  return {
    events: allFailed ? null : results,
    matchedNewsByGroup,  // ← v2 only: passed to geocoder
    bellingcatByGroup,   // ← v2 only: passed to geocoder
  };
}
```

```typescript
  const gt = loadGroundTruth(); // Load from .planning/eval/ground-truth-events.json

      if (dKm <= 20) w20++;
      if (dKm <= 100) w100++;

    within20km: w20,
    within100km: w100,

    await cacheSetSafe(BASELINE_KEY, score, BASELINE_TTL_SEC); // 90d TTL

  return score;
```

### 10. Known Failure Modes & Fixes (Phase 27.4 / 27.4.1 Artifacts)

**Batch 133/184 hang (27.4.1 D-01 root cause):**

- **Symptom:** v2 extractor batch stalled at 180s+ with no timeout (observed 2026-04-23)
- **Root cause:** Cerebras call hung indefinitely; no timeout existed
- **Fix:** Commit a5c8846 + D-01 — add `withBatchWatchdog()` wrapper with 90s hard kill, 60s soft-warn
- **Prevention:** All batches now auto-abort and DLQ-route after hard timeout

**Reasoning field length rejection (Commit a2ad342, D-12):**

- **Symptom:** Zod rejected whole batch when reasoning exceeded 200 chars; entire event group lost
- **Root cause:** System prompt said "≤200 chars" but no schema-level enforcement; verbose LLM models emit 200-400 char reasoning
- **Fix:** Change reasoning from `.max(200)` (reject) to `.transform()` truncate (keep batch alive)
- **Impact:** Reasoning now silently truncated @ 200 chars if LLM exceeds; batch succeeds

**Cerebras JSON schema maxLength rejection (Commit 8d325ee, wire schema update):**

- **Symptom:** Cerebras qwen-3-235b-a22b rejects `json_schema` with `maxLength` keyword
- **Error message:** `wrong_api_format: Invalid fields for schema with types ['string']: {'maxLength'}`
- **Root cause:** Cerebras structured output engine doesn't implement full JSON Schema validation keyword set that OpenAI/Groq do
- **Fix:** Remove `maxLength: 200` from wire schema `EVENT_EXTRACTION_SCHEMA_V2.properties.reasoning`; Zod still enforces locally
- **Impact:** Model is structurally unconstrained on reasoning length; Zod enforces on parse; failures route to DLQ

**Shape-drift `.map is not a function` (Commit e26ceca, defense-in-depth):**

- **Symptom:** `normalizeEventTypes(payload.data)` crashed with "events.map is not a function" (2026-04-24)
- **Root cause:** Phase 03 temporarily wrote LLMCachePayload envelope to terminal `events:llm:v2` key instead of events array
- **Fix:** Commit a5c8846 — split writes to `events:llm:v2` (terminal array-only) and `events:llm:v2:partial` (envelope-only)
- **Defense (D-09):** Added `toEntityArray()` and `coerceCachedEvents()` guards at every read site; shape coercion is synchronous and never throws
- **Prevention:** Future envelope write to terminal key survives as "serve empty, recompute from scratch" instead of 500 error

**Two-key cache split (Commit a5c8846, Phase 27.4.1 D-09):**

- **Symptom:** Partial progress snapshots with envelope shape leaked to terminal key → users got broken iteration errors
- **Fix:** Write split:
  - `events:llm:v2:partial` ← `LLMCachePayload` envelope (per-batch, complete=false → final complete=true)
  - `events:llm:v2` ← `ConflictEventEntity[]` only (after geocoding finishes)
- **Invariant:** /api/events reader NEVER touches partial key; only /llm-status and DevApiStatus read it
- **Impact:** Observable progress (DevApiStatus) decoupled from user-facing cache

**Cerebras model swap to qwen-3-235b (Commit 191708f, D-14 context):**

- **Symptom:** gpt-oss-120b access gated to higher tiers; free tier access removed
- **Root cause:** Cerebras tier escalation
- **Fix:** Swap `CEREBRAS_MODEL` to `qwen-3-235b-a22b-instruct-2507` (open on default tier)

#### **BATCH_SIZE**

- Current value: **2** (v2), **8** (v1 rollback)
- Tunable range: [1..8]
- **Impact of increase:** more groups per LLM call = lower provider utilization, but fewer batches overall; context window pressure increases (prompt size scales linearly w/ batch size)
- **Impact of decrease:** smaller batches = more API calls, lower per-call attention budget, but finer-grained timeout handling
- **Blast radius:** Changes `Math.ceil(groups.length / BATCH_SIZE)` for progress reporting; no cache version bump
- **Decision:** D-10 set to 2 because v2 enrichment blocks (NEWS + BELLINGCAT + TEMPORAL) consume 3-4x more prompt tokens than v1; narrower batches fit attention budget

#### **Retry / Backoff**

- **Retry attempts:** RETRY_ATTEMPTS = 2 (lines 23 of llm-provider.ts)
  - Tunable: [1..5] (higher = more resilience vs slower failure)
  - **Impact:** if first attempt fails, second fires at 1s backoff; both fail → next provider tried
- **Backoff schedule:** BACKOFF_MS = [1000, 4000] (exponential: 1s, then 4s for next attempt)
  - Tunable: slopes and intercepts
  - **Impact:** 4s delay absorbs transient network jitter; longer delay = slower failure signal
- **Jitter:** JITTER_MS = 250 (±250ms random)
  - Tunable: [0..1000]
  - **Impact:** spreading retry thunderherd (multiple workers don't hit provider simultaneously)

- **Primary:** `qwen-3-235b-a22b-instruct-2507` (Cerebras)
- **Fallback:** `openai/gpt-oss-120b` (Groq)
- Tunable: swap models (if gpt-oss-120b access is later granted to Cerebras, revert)
- **Blast radius:** None (constants only)
- **Impact:** gpt-oss-120b is larger model; may improve extraction quality but slower/more expensive

#### **Watchdog Timeout**

- **Hard timeout:** env var LLM_BATCH_TIMEOUT_MS (default 90000ms)
  - Tunable via environment: `LLM_BATCH_TIMEOUT_MS=120000` (no redeploy)
  - **Impact:** longer timeout = fewer DLQ entries, but slower failure signal; shorter = faster abort but higher false-timeout rate
- **Soft-warn:** hard-coded 60000ms (no env tunable)
  - Tunable: change constant in llmExtractorWatchdog.ts (requires redeploy)
  - **Impact:** amber markers help ops diagnose slow batches; if too close to hard timeout, may spam markers

### 12. Open Questions / Hypotheses for Phase 27.4.2 Tuning

1. **TEMPORAL block window inclusivity:** The ±72h window was chosen to capture regional campaign patterns, but does it include enough context for **border-region events** (Gaza/Lebanon where same-day cross-border reporting is high)? Hypothesis: narrowing to ±48h might reduce false positives by removing stale context; expanding to ±96h might catch strategic patterns. **Test:** compare eval score for 48h/72h/96h variants.

2. **2-pass verify short-circuit for single-candidate Nominatim hits:** WR-04 auto-accepts N=1 without LLM reranking. Is this gate **too aggressive** — are we accepting POI false positives? Hypothesis: some "Beirut airstrike" queries return [Beirut, Oregon] as only hit and auto-accept; reranker would've seen no ME candidates and rejected. **Test:** disable auto-accept, measure token budget vs eval accuracy trade-off.

3. **NEWS BLOCK time window (±24h) vs geographic relevance:** News matching is **time-only** (no haversine), so a Reuters article from Tel Aviv about a Gaza strike appears in an Iranian event's NEWS BLOCK if timing aligns. Is 24h too wide — should we narrow to ±12h or add optional haversine gate? Hypothesis: tighter time window reduces cross-region noise. **Test:** compare NEWS match relevance at 12h/24h/36h windows.

4. **BELLINGCAT coord precision in prompts:** Coords are embedded as `[lat, lat.toFixed(2), lng, lng.toFixed(2)]` (1km precision). Does 0.01-degree precision **help or hurt LLM reasoning**? Hypothesis: 4 decimal places may overspecify (LLM doesn't use coord arithmetic anyway); 2 decimals (100m) might be cleaner. **Test:** vary toFixed(0..4) and measure if reasoning quality changes.

5. **POI amenity inference keyword order:** POI_AMENITY_MAP maps landmarks like "nuclear refinery" to amenity "oil refinery". Are the inferences **correct for the ME theater**? Hypothesis: "refinery" should map to "oil refinery" (correct), but "power plant" might be dual-use (power generation vs. military facility). **Test:** spot-check 10 POI inferences against Nominatim results to validate mapping quality.

6. **Soft-cap threshold (80%) vs hard-cap (95%):** When Cerebras hits 80% daily budget, pipeline pauses but cached LLM keeps serving. Is 80% **too aggressive** (pauses too often) or **too lenient** (doesn't reserve enough headroom for spikes)? Hypothesis: 85% might balance between user experience and token reserve. **Test:** measure pause frequency at different ratios; compare token utilization.

7. **Circuit breaker error rate (30% of last 10 calls):** After 3 errors in last 10 calls, breaker trips for 5 min. Is 30% threshold **too sensitive** (brittle to transient spikes) or **not sensitive enough** (allows cascade failures)? Hypothesis: 50% (5 errors) might be more robust to jitter; 20% might catch failure faster. **Test:** inject transient errors and measure trip time.

8. **Nominatim cache TTL (30 days):** Geo-caches are long-lived (infrastructure is static). But if Nominatim data updates or a landmark name changes (e.g., renamed facility), stale cache persists. Is 30d **too long**? Hypothesis: 14d strikes better balance. **Test:** deploy with variable TTLs and measure facility-rename detection lag.

9. **DLQ max size (200 entries, 7-day TTL):** Bounded at 200 with oldest eviction. Is this **too small** (lose failure history too fast) or **too large** (memory waste)? Hypothesis: 500 entries might capture more failure patterns without harm; 100 might be too aggressive. **Test:** monitor DLQ saturation rate over 2 weeks of ops.

10. **News source tier weighting in NEWS BLOCK:** T1/T2/T3 tags are displayed but LLM doesn't receive explicit weights. Should we **reorder articles by tier** (T1 first) or **prepend tier probability** to LLM prompt? Hypothesis: explicit reordering helps LLM prioritize credible sources. **Test:** render NEWS BLOCK as {T1: [...], T2: [...], T3: [...]} and measure extraction quality.
