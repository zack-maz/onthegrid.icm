<objective>
Tag every newly-extracted v3 event with `providerProvenance` (additive-optional Zod field), then aggregate per-provider eval scores in `runEval()` and surface them in the API Health dashboard's `EvalScoreBlock`. Per-provider scoring lets operators detect silent quality regression on any restored provider against the NIM baseline.

Purpose: Without `providerProvenance` at write-time, the eval harness cannot bucket cached entries by provider without re-extraction (which doubles LLM token spend — CONTEXT D-16 invariant). This plan ships the cheapest, lowest-risk addition that makes per-provider eval real.
Output: Schema extension + extractor write-site + harness aggregation + dashboard surface + tests + per-provider baseline Redis key.
</objective>
