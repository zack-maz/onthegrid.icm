# Phase 39 — UI Design Contract

> Visual and interaction contract for the two new operator-facing blocks — `BudgetBlock` and `FlightRecorderBlock` — that mount into the existing `src/components/ui/DevApiStatus.tsx` API Health tab. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a brownfield phase.** The design system is ALREADY LOCKED by `DevApiStatus.tsx` (a 3,100-line dark operator-console surface) and `src/styles/app.css` `@theme`. This contract does NOT invent tokens — it transcribes the existing idiom the two new blocks must conform to, then locks the block-specific information hierarchy, the proximity-bar encoding, outcome-color semantics, copy, and degraded/empty/loading states. Per CONTEXT GA-1 the scope is a FUNCTIONAL-but-clean baseline; rich filters + tab/subtab placement defer to Phase 40.

## Design System

| Property          | Value                                                                                                                                                                |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tool              | none (hand-rolled Tailwind v4 utility classes — no component library exists in this repo)                                                                            |
| Preset            | not applicable                                                                                                                                                       |
| Component library | none (no `components.json`; no radix/base-ui; bespoke React + Tailwind)                                                                                              |
| Icon library      | none — uses Unicode glyphs (`→`, `·`, `…`) and CSS shapes (`rounded-full` dots, `rounded` pill badges) inline, matching existing `StageIndicator` / status-dot idiom |
| Font              | system-ui sans (`app.css` base) for chrome; **`font-mono` for all data/numeric content** (existing convention — modal at `:696`, every metric row uses `font-mono`)  |

**Styling discipline (from CLAUDE.md "Color Tokens" + Tailwind v4 CSS-first):**

- No `tailwind.config.js` — Tailwind v4 `@theme` block in `src/styles/app.css` is the single source of truth.
- No inline hex/RGBA literals in consumers where a semantic token exists. The four `--color-accent-{blue,red,green,yellow}` OKLCH tokens are the operator status palette and are reachable as Tailwind utilities `text-accent-red`, `border-accent-yellow`, `bg-accent-green`, etc.
- The 24 entity `--color-*` tokens (flight/ship/event/site/faction/ethnic) are for the MAP, **not** this operator surface. Do NOT pull entity colors into `BudgetBlock`/`FlightRecorderBlock`. The operator console uses the neutral `white/N` opacity ramp + the four accent tokens only.
- Both new blocks are children of `DevApiStatusAllApisTab` (`:871`); they inherit its `font-mono text-[10px] text-white/80` context.

## Spacing Scale

The host renders inside a `font-mono text-[10px]` panel using a **dense console spacing rhythm** (NOT the generic 8-point app scale — this is the locked exception for this operator surface, see Exceptions). Declared values used by the new blocks, all multiples of 4:

| Token | Value | Tailwind                           | Usage                                                                           |
| ----- | ----- | ---------------------------------- | ------------------------------------------------------------------------------- |
| xs    | 4px   | `gap-1` / `px-1` / `py-1` / `mt-1` | Inline metric gaps, badge padding, label-to-value gap                           |
| sm    | 8px   | `gap-2` / `px-2` / `py-2` / `mb-2` | Row padding, block-internal stacks, between-bar gaps                            |
| md    | 12px  | `px-3` / `py-3`                    | Section horizontal padding (matches existing `px-3` rows), modal header padding |
| lg    | 16px  | `mt-4` / `px-4`                    | Block-to-block separation, modal body padding                                   |
| xl    | 24px  | `gap-6` (rare)                     | Reserved — major drill-down panel breaks only                                   |

Section separators reuse the locked host idiom verbatim: `mt-2 border-t border-white/10 pt-2` between sibling sections; `mt-4` before a new top-level block (matches Operator Actions `:1549`).

Exceptions:

- **Dense console scale is intentional and locked.** This operator/dev surface uses 4/8/12 px rhythm and 1px hairline borders (`border-white/10`), NOT the 16/24/32 app-shell scale. This matches every existing sub-block in `DevApiStatusAllApisTab` and is required for visual consistency. A 16px-baseline rewrite would make the new blocks look foreign in their host. The gsd-ui-checker MUST evaluate spacing against THIS host-conformant scale, not the greenfield default.
- Proximity/progress bars are `h-1` (4px) track height — the locked `ProgressBar` height (`:112-116`). Drill-down call-timing bars MAY use `h-1.5` (6px) to differentiate, matching status-dot `h-1.5` usage.

## Typography

The host locks a 4-size monospace micro-scale. The new blocks MUST use only these sizes (no new sizes introduced):

| Role            | Size | Weight        | Line Height   | Tailwind                                                       | Usage                                                                                                                                   |
| --------------- | ---- | ------------- | ------------- | -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Section header  | 9px  | bold (700)    | normal (~1.4) | `text-[9px] font-bold uppercase tracking-wider text-white/40`  | Block + sub-section titles ("TOKEN BUDGET", "FLIGHT RECORDER", "RUNS", "CALLS") — verbatim host idiom (`:1536`, `:1782`, `:1810`, etc.) |
| Body / metric   | 10px | regular (400) | normal (~1.4) | `text-[10px] font-mono`                                        | All metric values, run-list rows, call rows, USD/token numbers (`tabular-nums` on numerics)                                             |
| Emphasis label  | 11px | bold (700)    | normal        | `text-[11px] font-bold uppercase tracking-wider text-white/50` | Drill-down modal/header titles only (matches modal header `:702`)                                                                       |
| Micro / caption | 8px  | regular (400) | normal        | `text-[8px] text-white/40 tabular-nums`                        | Percentage suffixes on bars, "x of y" counts, secondary timestamps (matches `ProgressBar` pct `:118`)                                   |

Weights: exactly **2** — regular (400) for data, bold (700) for headers/labels. No other weights. (The host uses `font-medium`/`font-semibold` in tab-chip chrome only; the new data blocks stay on 400/700.)

Numeric values: always `tabular-nums` so token counts, USD, and percentages don't jitter on poll-refresh.

## Color

This is a dark surface. The "60/30/10" reads as surface / hairline-structure / status-accent. The new blocks pull ONLY from `--color-surface*`, the `white/N` neutral ramp, and the four `--color-accent-*` tokens.

| Role            | Value                                    | Token                                    | Usage                                                                                                                                                                                               |
| --------------- | ---------------------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dominant (60%)  | `oklch(0.145 0 0)` / `bg-black/85`       | `--color-surface`, `bg-black/85` (modal) | Panel background, block backgrounds (inherited from host; blocks add no opaque fill)                                                                                                                |
| Secondary (30%) | `white/5`–`white/10`                     | `bg-white/5`, `border-white/10`          | Bar tracks (`bg-white/10`), row hover (`hover:bg-white/5`), hairline separators (`border-white/10`), nested cards (`border border-white/5 bg-white/5`)                                              |
| Accent (10%)    | the four `--color-accent-*` OKLCH tokens | `accent-blue / red / green / yellow`     | Status/outcome semantics ONLY (see semantic table below) — never decorative                                                                                                                         |
| Destructive     | `--color-accent-red`                     | `accent-red` / `text-red-400`            | Hard-cap breach, `error`/`timeout` run outcomes, DLQ counts > 0. **No destructive ACTIONS in this phase** — both blocks are read-only; `accent-red` here is a STATUS color, not a delete affordance |

Accent reserved for (explicit list — never "all interactive elements"):

- **`accent-green` (success):** budget bar below soft threshold (< 0.8); run outcome `success`; healthy/connected state.
- **`accent-yellow` (warning):** budget bar in soft band (≥ 0.8 and < 0.95); run outcome `partial`; DLQ present but bounded; "approaching cap" copy.
- **`accent-red` (critical):** budget bar at/over hard threshold (≥ 0.95); run outcomes `timeout` and `error`; hard-cap breach.
- **`accent-blue` (running / informational):** run outcome `running` (in-flight, from GA-2 start-write); the live batch-progress bar fill; neutral "cron" source tag (matches existing `border-accent-blue` cron tag `:822`).
- **neutral `white/40`–`white/50`:** all non-status text, labels, idle/unknown states, the "running"-bar track. The DEFAULT for anything not carrying status meaning.

**Outcome / status color semantics (locked — used by both blocks):**

| State                      | Color token     | Bar/badge                                    | Where                                                                       |
| -------------------------- | --------------- | -------------------------------------------- | --------------------------------------------------------------------------- |
| `running`                  | `accent-blue`   | blue fill + animated/indeterminate batch bar | Flight-recorder run badge; live budget poll                                 |
| `success`                  | `accent-green`  | green badge                                  | Run outcome badge                                                           |
| `partial`                  | `accent-yellow` | yellow badge                                 | Run outcome badge (some groups DLQ'd / some calls failed but run completed) |
| `timeout`                  | `accent-red`    | red badge                                    | Run outcome badge (watchdog 90s hard-kill)                                  |
| `error`                    | `accent-red`    | red badge                                    | Run outcome badge (unhandled / fatal)                                       |
| budget < 0.8               | `accent-green`  | green proximity bar                          | BudgetBlock per-provider bar                                                |
| 0.8 ≤ budget < 0.95 (soft) | `accent-yellow` | yellow proximity bar + soft tick             | BudgetBlock                                                                 |
| budget ≥ 0.95 (hard)       | `accent-red`    | red proximity bar + hard tick                | BudgetBlock                                                                 |

Use the existing `STATUS_PILL_CLASSES` / `TIER_BORDER_CLASSES` idiom (`rounded ... px-2 py-1 text-[9px] font-bold uppercase tracking-wider` + a colored `border`/`bg-{color}/10 text-{color}-400`) for run-outcome badges so they match the endpoint status pills already on the tab (`:1454`, `:1461`).

## Component & Interaction Contract

This is the load-bearing section for executor + planner. Two blocks, both children of `DevApiStatusAllApisTab`, both sourced from one extra `/api/operator-status` field (`tokenBudget`) plus one new Bearer-gated endpoint (`GET /api/events/llm-history`).

### A. BudgetBlock

Mounts as a new `<div className="mt-2 border-t border-white/10 pt-2">` section inside `DevApiStatusAllApisTab` (alongside the actorQuality / prune sub-blocks, ~`:1781`). Data: the new `tokenBudget` field on the already-polled `OperatorStatus` shape (GA-4 provider-keyed map: `{ providers: { nvidia_nim: { used, cap, soft, hard, state } }, costShadow: { tokensIn, tokensOut, usd } }`). No new fetch — reuses the existing 30s `fetchOpStatus` poll.

Information hierarchy (top → bottom):

1. **Section header** — `TOKEN BUDGET` in the `text-[9px] font-bold uppercase tracking-wider text-white/40` idiom.
2. **Per-provider proximity bar** (one row per `providers` map entry; today only `nvidia_nim`):
   - Left: provider label (`text-[10px] text-white/60`, e.g. `NIM`).
   - Center: a proximity bar reusing the `ProgressBar` h-1 rounded-full track (`bg-white/10`), fill width = `used / cap`, fill color from the budget semantic table (green/yellow/red by band).
   - The bar carries TWO static threshold ticks — a soft tick at 80% and a hard tick at 95% (1px `bg-white/30` vertical marks overlaid on the track) so the operator sees proximity, not just a raw fill.
   - Right: `text-[8px] text-white/40 tabular-nums` showing `{used}/{cap}` and the `state` word (`ok` / `soft` / `hard`).
3. **Cost-shadow row** — today's USD: `Cost today: $X.XX` (`text-[10px] font-mono`), with `tokensIn`/`tokensOut` as a `text-[8px] text-white/40` caption. USD is rendered to 4 decimal places (micro-cent precision; values are tiny). Per GA-3, ship **today only** + a soft/hard proximity context; the 90d sparkline is DEFERRED (do not fan out 90 Redis GETs per poll). If planning later adds a thinned 7-day strip it reuses the h-1 bar idiom — but that is out of the 39 baseline scope.

Interaction: **read-only, no drill-down in 39.** No click targets. (Rich filters/expansion defer to Phase 40 per GA-1.)

### B. FlightRecorderBlock

Mounts as a new top-level section (`mt-4 px-3 py-2`, matching Operator Actions `:1549`) inside `DevApiStatusAllApisTab`. Data: new Bearer-gated `GET /api/events/llm-history` → `{ runs: [...], calls: [...] }` (optional `?runId=X` / `?limit=N`). Fetched with `dashboardAuthHeaders()` on tab-open + the existing poll cadence; degrade-open like every other operator block.

Three-level information hierarchy ("scrub the flight recorder"):

**Level 1 — Run list** (default view, newest-first):

- Section header `FLIGHT RECORDER` then a sub-header `RUNS` (`text-[9px]` idiom).
- Each run = one clickable row (`cursor-pointer hover:bg-white/5`, the locked expandable-row idiom from the endpoint table `:1447`):
  - **Outcome badge** — pill using `STATUS_PILL_CLASSES` idiom, colored by the outcome semantics table (`running`=blue, `success`=green, `partial`=yellow, `timeout`/`error`=red).
  - **Run id + start time** — `text-[10px] font-mono text-white/60`, time as relative age (`freshnessText`/`formatAge` already exist in host).
  - **Batch progress bar** — the `ProgressBar` h-1 component, `completed/total` groups; blue fill while `running`, green when `success`.
  - **Token spend** — `text-[8px] tabular-nums` (`{tokens} tok`).
  - **Eval score** — `text-[8px] tabular-nums`, colored green ≥ 0.95 / yellow ≥ 0.80 / red below (matches eval-gate thresholds in CLAUDE.md).
- Selecting a run sets a local `selectedRunId` and reveals Level 2 (inline expansion below the row, or a slide-in detail — planner picks; default is inline expansion to match the host's existing expand-row pattern, NOT a new modal, for the 39 functional baseline).

**Level 2 — Call list for the selected run** (filtered by `runId`):

- Sub-header `CALLS` (`text-[9px]`).
- One row per call (`callHistory` entry + `runId` + `batchIndex`): `text-[10px] font-mono` row showing batch index, per-call timing bar (`h-1.5`), provenance tag (resolver path / provider), and a status glyph (ok dot / DLQ marker / timeout marker) colored by the same semantic ramp.
- Aggregate sub-strips for the run: provenance distribution (count per resolver path), DLQ groups (count; yellow if > 0), watchdog timeouts (count; red if > 0) — each a one-line `text-[10px]` summary, NOT a chart (charts defer to a future analytics phase per CONTEXT "Deferred Ideas").
- Selecting a call reveals Level 3.

**Level 3 — Single-call drill-down** (prompt / response):

- The prompt + raw response for the selected call. Reuse the existing copyable code-panel modal idiom (`font-mono text-[10px]`, the `Copied!` affordance at `:758`, `bg-black/85` backdrop) — this surface already exists for other drill-downs; mirror it rather than inventing.
- Per GA-1, the prompt-copy "nicety" is allowed to be MINIMAL in 39 (show prompt/response text; the polished copy-button + syntax niceties can lean on the existing modal component or defer to Phase 40). Baseline requirement: the operator CAN read a single call's prompt+response. Rich formatting is not gated.

Interaction model summary: **list → expand-run → expand-call → read prompt/response.** Newest-first ordering. No destructive actions. No editing. Drill-down state is local React state (mirrors the host's `expandedRow` / `selectedRow` pattern `:882`), transient, not persisted.

### Empty / Loading / Degraded states (degrade-open is mandatory — every operator block follows it)

| Condition                                             | Block                  | Treatment                                                                                                                                    |
| ----------------------------------------------------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `tokenBudget === null` (Redis throw, route still 200) | BudgetBlock            | Render gate hides the block entirely (mirrors `opStatus?.actorQuality != null` gate `:1681`). No error chrome — silent graceful unavailable. |
| `tokenBudget.providers` empty                         | BudgetBlock            | Show header + a `text-[10px] text-white/30` line: `No provider budget data yet`.                                                             |
| `/api/events/llm-history` non-200 / network fail      | FlightRecorderBlock    | Block hides (try/catch swallow, degrade-open) — same idiom as `fetchOpStatus` `:958`.                                                        |
| `runs` empty (cold cache, no run has executed)        | FlightRecorderBlock    | Header + `text-white/30`: `No runs recorded yet` (mirrors `No LLM runs yet` `:164`).                                                         |
| Selected run has no `calls`                           | FlightRecorderBlock L2 | `text-white/30`: `No calls recorded for this run`.                                                                                           |
| In-flight fetch, no prior data                        | Both                   | Reuse the host skeleton idiom: `h-6 animate-pulse rounded bg-white/5` placeholder rows (`:1392`).                                            |
| Run currently `running` (GA-2 start-write)            | FlightRecorderBlock    | Blue badge + indeterminate/animated batch bar; row stays at top; updates in place on next poll to terminal outcome.                          |

## Copywriting Contract

All operator-facing, terse, console-register, lower-noise. Numbers over narratives (project ethos).

| Element                                                   | Copy                                                                                                                       |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| BudgetBlock section header                                | `TOKEN BUDGET`                                                                                                             |
| BudgetBlock provider row (state words)                    | `ok` / `soft` / `hard` (lowercase, matches `budgetState`)                                                                  |
| BudgetBlock cost line                                     | `Cost today: $0.0000` (4dp)                                                                                                |
| BudgetBlock cost caption                                  | `{tokensIn} in · {tokensOut} out`                                                                                          |
| BudgetBlock approaching-cap (soft)                        | `Approaching cap` (yellow)                                                                                                 |
| BudgetBlock at-cap (hard)                                 | `Hard cap reached` (red)                                                                                                   |
| BudgetBlock empty                                         | `No provider budget data yet`                                                                                              |
| FlightRecorderBlock section header                        | `FLIGHT RECORDER`                                                                                                          |
| Run-list sub-header                                       | `RUNS`                                                                                                                     |
| Call-list sub-header                                      | `CALLS`                                                                                                                    |
| Empty run-list heading                                    | `No runs recorded yet`                                                                                                     |
| Empty run-list body                                       | `LLM extraction runs appear here after the next cron tick (04:00 UTC) or a forced refresh.`                                |
| Empty call-list                                           | `No calls recorded for this run`                                                                                           |
| Run outcome labels (badge text)                           | `RUNNING` · `SUCCESS` · `PARTIAL` · `TIMEOUT` · `ERROR` (uppercase pill text)                                              |
| Run row metric labels                                     | `{n} tok` · `eval {score}` · `{done}/{total} groups`                                                                       |
| Call provenance / DLQ / watchdog summaries                | `Provenance: {path} ×{n}` · `DLQ: {n} groups` · `Timeouts: {n}`                                                            |
| Degraded / unavailable (both blocks)                      | (silent — block hides; no visible error text per degrade-open)                                                             |
| Error state (only if a non-degrade-open failure surfaces) | `Budget data unavailable` / `Flight recorder unavailable` (`text-white/40`, no stack, no retry button — read-only surface) |

**No destructive actions in this phase.** Both blocks are strictly read-only (Bearer-gated reads). There are no delete/prune/replay affordances added by Phase 39, therefore no destructive-confirmation copy. (Existing prune/replay affordances elsewhere on the tab are out of this phase's scope.)
